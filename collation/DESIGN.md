# AI 古籍校对系统 · 方案设计

> 兰木（lan_mu）的上游校勘子系统。核心理念承自兰木「一次校录，多态呈现」——
> 校勘子系统负责把**扫描善本**与**现代点校本**经多智能体校对，产出两份可复用的点校文本；
> 其中「善本点校本」可直接喂入兰木 songke 引擎，成为 `works/<id>/text.yaml` 的来源。

---

## 0. 一句话定位

> 选择公开善本为底本 → OCR → AI 初校 → 视觉复核 → 对校（善本 vs 现代本）→ 校书官逻辑顺通 →
> 出具「善本点校本（公开）」与「现代本（自用）」两份文本 → 人工复核悬置疑问。

本系统是这条链路的**可运行实现**，以 `input_data/` 下的《大学章句》《中庸章句》为实证案例。

---

## 1. 设计目标

1. **可复现**：同一份 input_data + 同一版本代码，产出逐字节一致的校勘结果（承兰木确定性渲染观）。
2. **多源对校**：善本（当涂郡斋刊递修本）与现代点校本（儒藏精华编）双轨进入，AI 居间对校。
3. **多智能体裁决**：以古代校书官（刘向、解缙、戴震、纪昀）为角色画像的智能体，对异文各陈意见、出结论或悬置、陈列各方靠谱意见。
4. **双本分流**：
   - **善本点校本**——以公开善本为底、新加句读，可公开传播；
   - **现代本**——以现代点校本为底，供自修研读，不外传。
5. **人机闭环**：悬置疑问落成 `flags`，待人工终裁；终裁结果回写，反哺下一轮。

## 2. 七阶段流水线

```
┌──────┐   ┌──────┐   ┌────────┐   ┌──────────┐   ┌──────┐   ┌────────┐   ┌──────┐   ┌──────────┐   ┌──────┐
│ P0   │──▶│ P1   │──▶│ P2     │──▶│ P2.5     │──▶│ P3   │──▶│ P4     │──▶│ P5   │──▶│ P6       │──▶│ P7   │
│ 装载 │   │ OCR  │   │ AI初校 │   │ 视觉复核 │   │ 对齐 │   │ 对校   │   │ 校书 │   │ 双本出具 │   │ 人工 │
└──────┘   └──────┘   └────────┘   └──────────┘   └──────┘   └────────┘   └──────┘   └──────────┘   └──────┘
   io.js    ocr.js*    llm.js        reconfirm.js   align.js    diff.js     officer.js   export.js     flags
                                                                 +punctuate.js
```
\* P1 在本系统为可选——`input_data/` 已附 OCR 成果；若需对新扫描件补跑，复用 `tools/pointcheck/ocr.js`（tesseract → txt+tsv）。

### P0 装载（`src/io.js`）
读 `input_data/<书名>/{当涂郡本,儒藏本}_ocr/page_*.md` + `_pdf/` 页索引，构造两个 `Edition` 对象：
```
Edition { id, role:'shanben'|'xiandai', pages:[{n, raw}], pdfCount }
```
- 善本：`raw` = 逐行原文（保留断行，供 P3 去断行）。
- 现代本：`raw` = 逐行原文（保留标点、○、脚注标记，供 P3 切句与剥离校记）。
- 跳过封面页（善本 page_0001「宋本大學章句」之类）。

### P1 OCR（外部 / 已就绪）
`input_data/` 的 OCR 已完成。`tools/pointcheck/ocr.js` 提供补跑能力（pdf→pdftoppm→tesseract→txt+tsv，tsv 保留 bbox/字高/置信度）。tsv 的字高信息是**善本经(j)/注(z)区分的唯一可靠来源**——flat 的 OCR md 已丢失大小学，需 tsv 或视觉复核补回。

### P2 AI 初校（`src/llm.js` 驱动）
对两本 OCR 各做结构化清洗：
- **善本**：异体归一备查（不改正文，仅登记形→标形映射）、低置信字标疑难、按 tsv 字高或视觉初判经/注边界（无 tsv 则整段待 P2.5 视觉判）。
- **现代本**：剥离脚注（①②…）与正文校记（"X 本作…"），区分**原文**与**校记**；规范引号、○。
- LLM 介入点：残字/异体难定时，给候选 + 置信；规则基线先跑，疑难转 LLM。
- **mock 兜底**：无 API key 时走确定性规则基线，保证全链可跑。

### P2.5 视觉复核（`src/reconfirm.js`）
对善本扫描件**再调**模型确认 P2 标记的疑难字：
- 优先调视觉理解模型（VLM）读善本扫描 PDF 对应页，回填候选字；
- 次选对扫描件重跑 OCR（tesseract/另一引擎）做交叉验证；
- 结果写回异文条目的 `reconfirm` 字段（候选 + 依据 + 置信）。
- 无模型时：标记 `reconfirm:'deferred'`，转入 P7 人工。

### P3 对齐（`src/align.js`）
两本异质（善本无标点断行 / 现代本有标点注夹），需先归一再对齐：
1. **善本**：跨页拼接去断行 → 连续字串；跳过封面。
2. **现代本**：保留正文与注，剥离脚注/校记（另存 `xiandaiNotes`）；去标点、去 ○、去空白 → 连续字串。
3. **归一**：异体归一表（丗→世、彞→彝、頺→頽、𣎆→… 等，及 opencc tw 内部一致）→ 两本各自 `norm` 字串。
4. **句级对齐**：以句号/章界为锚，对 `norm` 串做 LCS+滑动窗口，产出对齐段 `Aligned{ shanben:[{n,text}], xiandai:[{n,text}], score }`。
   - 锚点：朱子章句结构（经一章、傳十章之「右傳之X章」标记）是强锚，优先对齐。
5. 不可对齐段（一方无对应）→ 标 `orphan`，多半是夺/衍或页序问题，转 P4。

### P4 对校（`src/diff.js`）
对每个对齐段做字级 diff，产出异文 `Variant{ id, segId, type, shanben, xiandai, pos, note }`：
- `异体`（同字异形，归一后即合）——登记善本用形，非真异文。
- `ocr疑`（善本 OCR 可能误读，归一后仍不合且现代本统一）——转 P2.5/P7。
- `真异文`（两本用字实不同，如"親/新""矣"之有无）——**校书官主战场**。
- `夺/衍/倒`（一多一少/顺序颠倒）。
- 每条带两侧上下文（前后各 6 字）便于人读。

### P5 校书官逻辑顺通（`src/officer.js` + `src/punctuate.js`）
本系统心脏。四校书官（智能体扮演）对**真异文**逐条审议：
1. **各陈意见**：每位校书官依其方法论独立给判断（采纳善本/采纳现代本/另立/存疑）+ 理据。
2. **陈列**：把各方靠谱意见并陈，不搞多数表决——考据从理不从众。
3. **出结论**：能定者给定论（`resolved`）+ 采纳方 + 据何本何据。
4. **悬置**：难定者给**暂拟结论**（`suspended`，倾向某方但标注未决）+ 列待查线索。
- **句读顺通**（`punctuate.js`）：对善本正文加句读（点校）——以现代本句读为初稿，校书官按文理修正（如"○"分隔注起、章界换段）。
- 校书官画像见 `officers/`，既供 Node 端 LLM 调用（system prompt），亦可由 Claude Code Agent 工具实跑 live 裁决。

### P6 双本出具（`src/export.js`）
- **善本点校本.md**（公开）：以善本为底 + P5 句读 + 校书官定论以夹注/脚注形式附（仅公开善本依据）。
  - 凡涉现代本独有之字（非善本所有），**不收入正文**，仅于校记注"某本作X"——保公开底本纯净。
- **现代本.md**（自用）：以现代本为底，附校书官对异文的全部意见（含善本异）+ 悬置疑问。
- 两本均附 `校勘记`（异文表 + 裁决 + 悬置），现代本校勘记更详（含自用研究意见）。

### P7 人工复核（`flags.yaml`）
P5 悬置疑问 + P2.5 deferred + P4 ocr疑，汇成 `flags`。人工逐条终裁，回写 `verdicts.json` 的 `human` 字段；重跑 P5/P6 即吸收。形成「AI 出初稿 → 人工终裁 → 回写」闭环。

## 3. 版本登记与法理依据（`config/editions.yaml`）

| 角色 | 版本 | 授权级 | 用途 | 法理 |
|---|---|---|---|---|
| 善本（底本） | 当涂郡斋刊递修本（南宋，国图藏） | A 公开 | 善本点校本之底 | 公开善本，公有领域；新加句读为原创点校，可公开传播 |
| 现代本（对校本） | 儒藏精华编第 110 册 | B 自用 | 对校 + 现代本之底 | 现代点校有整理者著作权；仅供自修，不入 dist、不外传 |

> 双本分流即法理分流：善本点校本只引善本之字，现代本只供己用——两条线物理隔离，
> 善本点校本永远不混入现代本受著作权保护的整理成果。

## 4. 校书官制度（`officers/`）

四官取法历代校书传统，各具方法偏重，互为补正：

| 官 | 时代 · 据实原型 | 方法论偏重 |
|---|---|---|
| **刘向** | 西汉 · 校雠鼻祖 | 辨章学术、考镜源流；重篇第错简、序录源流。主"本校/他校"。 |
| **解缙** | 明 · 永乐大典总纂 | 博闻强记、类书旁证；以群籍互参定字。主"他校"。 |
| **戴震** | 清 · 朴学考据 | 实事求是、由字以通词由词以通道；重音韵训诂、本字本义。主"理校/训校"。 |
| **纪昀** | 清 · 四库总纂 | 折中定谳、不执一端；综众说取平、明列不强断。主"折中"。 |

裁决规则：**从理不从众**——四官意见并列陈列，不一意求同；能定给定论，难定给暂拟 + 线索，绝不强不知以为知。

## 5. 数据模型（中间产物，`data/<书名>/`）

```
aligned.json     P3 → [{segId, shanben:[{n,text}], xiandai:[{n,text}], score, orphan?}]
diffs.json        P4 → [{id, segId, type, shanben, xiandai, ctx, reconfirm?}]
verdicts.json     P5 → [{diffId, opinions:[{officer, adopt, reason}], verdict:'resolved'|'suspended', adopt?, note, human?}]
punctuated.json   P5 → 善本带句读结构（章节/经注/句读）
output/
  善本点校本.md     P6（公开）
  现代本.md         P6（自用）
  校勘记.md         P6（异文表 + 裁决 + 悬置）
flags.yaml        P7 → 人工待办
```

## 6. AI 模型接入策略（`src/llm.js`）

- **可插拔**：优先 `ANTHROPIC_API_KEY`（Claude）；次 `DASHSCOPE_API_KEY`（通义千问，OpenAI 兼容端点）。
- **mock 兜底**：无 key 时走确定性规则基线（异体归一、句读模板、按异文类型给倾向性意见），**明确标注 `engine:'mock'`**，保证全链可跑可验、结果可复现。
- **结构化输出**：所有 LLM 调用强制 JSON schema（候选字/置信/理据/采纳方），规避自由文本解析。
- 校书官 system prompt 即 `officers/*.md` 的画像，Node 端与 Claude Code Agent 端共用同一份，确保 live demo 与批跑一致。

## 7. 与既有设施的关系

- **`tools/pointcheck/`**：即本系统的 P1（`ocr.js`）+ P2 规则基线（`ai.js`）。本系统**延伸而非替代**之——pointcheck 止于"草稿 text.yaml + flags"，本系统续上对校→校书官→双本出具。
- **`works/<id>/text.yaml`**：兰木 songke 引擎的最终消费品。本系统产出的**善本点校本**经人工复核后，可转写为 `text.yaml`（`sections[].blocks[]{type:j|z,text}`），成为 `works/daxue`、`works/zhongyong` 的**善本底**来源（现为通行本）。
- **`input_data/`**：gitignored 源数据（体量大），不入仓库；本系统运行期读此目录，产物写 `collation/data/`（可入仓的小体量 JSON/MD）。

## 8. 用法

```bash
# 全链跑一部作品（无 API key 走 mock，仍产出完整双本）
node collation/run.js 大学章句
node collation/run.js 中庸章句

# 指定阶段
node collation/run.js 大学章句 --step=align
node collation/run.js 大学章句 --step=diff

# 真实 LLM（置 env 后）
ANTHROPIC_API_KEY=... node collation/run.js 大学章句
```

产物见 `collation/data/大学章句/`。

## 9. 局限与后续

- 善本经/注大小学在 flat OCR md 中已丢失，须经 tsv 字高或视觉复核补回；当前 mock 流程对经注边界取保守策略（整段不细分），真实部署需补 tsv 或 VLM。
- 句读点校的"点"之斜正轻重（兰木 `calligraphy.js` 的笔墨微变换）不在本系统范畴，由下游引擎按 seed 生成。
- 论语、孟子集注体量巨大（445/547 页善本），当前实证止于大学、中庸；流水线设计已为大批量留好分页/分批接口。
