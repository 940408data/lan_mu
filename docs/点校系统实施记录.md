## P1 实现：OCR 管路（`tools/pointcheck/ocr.js`）

### 设计
- 输入：pdf 或 jpg/png + 输出目录 + `--lang`（默认 chi_tra 善本繁体）+ `--dpi`（默认 300）。
- pdf→页图：`pdftoppm -png -r 300 <pdf> <prefix>`。
- 图→OCR：每页 `tesseract <img> <base> -l <lang>`（txt）+ `tesseract <img> <base> -l <lang> tsv`（bbox+置信度）。
- 输出：`<outdir>/pages/page-NNN.txt` + `page-NNN.tsv` + `combined.txt`（全文）+ `manifest.json`（页映射+引擎+lang+dpi）。

### 测试
- **小图 line.png（523×26）**：`node tools/pointcheck/ocr.js input_data/chm_extract/image/line.png /tmp/ocr-line` → 1 页 5 字（`~ 一 有 和對`），< 1 秒，管线通。✓
- **大图 youlan/scan.jpg（1.6MB 书法手卷）**：`--lang=chi_tra` 超时（>120s 未完成），tesseract 在书法/竖排上极慢。

**【踩坑#2】tesseract 对书法/竖排大图极慢且质量差**：幽兰 scan.jpg（1.6MB 书法手卷）>120s 超时未完。原因：tesseract 对竖排、无标点、异体字、毛笔书法版面的版面分析弱、逐字识别慢。

**【经验】**：
- tesseract 适合**点校本**（横排、有标点、印刷体）OCR；**善本**（竖排、书法、异体字）应上 PaddleOCR（竖排版面模型）或 LLM vision（Claude 读图，异体字/残字强）。
- 大图先**分页/切块**再 OCR（避免单次超时）；善本可按列预切（竖排→列→字）。
- dpi 300 够清；过低识别率降，过高变慢。

## P2 实现：AI 初校（`tools/pointcheck/ai.js`，规则基线）

### 设计
- 输入：`ocr.js` 产出的 `<outdir>/pages/page-NNN.tsv`（含每字 bbox + height + conf）。
- 经/注聚类：按 tsv 的 `height`（字高）分——高于中位字高 15% 视为大字（经 j），低于为小字（注 z）；连续同类归块，类切换另起。
- 转换：opencc `s2tw` + CORRECT 表（嘆→歎 等 9 字，与 extract-*.js 一致）+ 引号 `""''`→`「」『』`。
- 疑难标注：置信度 < 60 的块入 `flags.yaml`（页+类型+置信度+文本+「建议人工/LLM 复核」）。
- 输出：`<outdir>/draft-text.yaml`（草稿）+ `flags.yaml`（疑难点）。

### 测试
- 在 line.png OCR 输出上跑：1 块（z，`~一有和對`），1 个低置信 flag（conf 19.0）。管线通，但单行小图无经/注区分（全 z），结果噪声大。

**【踩坑#3】规则基线经/注聚类粗糙**：按字高聚类对**清晰版面**有效，但善本竖排的列序、大小字交错、章界需更稳的版面分析；单行/小图聚类无意义。

**【经验】**：
- 规则基线作**清晰点校本**或**版面规整善本**的初校可；**疑难善本**（竖排、异体字、残字、经注难辨）应转 LLM（Claude API）——LLM 读图直接给结构化 + 异体字正字 + 残字推断，远胜规则。
- tsv 的 `height` 是经/注聚类的关键信号（大字高、小字矮）；但需先有正确的版面/列分析（竖排善本）。

**【下一步 P2 增强】**：接 LLM（Claude API，`@anthropic-ai/sdk`）做结构化——prompt 含 OCR 文本 + 善本页图（vision），让 LLM 输出 j/z 块 + 异体字正字 + 残字 + 章界，规则基线仅作 LLM 不可用时的回落。需配 Claude API key。

## 踩坑与经验汇总

1. **环境无 OCR/pdf 工具**（#1）→ apt 装 tesseract+poppler（需 sudo）。
2. **tesseract 对书法竖排慢且差**（#2）→ 善本上 PaddleOCR 或 LLM vision；tesseract 留点校本。
3. **规则经/注聚类粗糙**（#3）→ 接 LLM 做结构化；规则作回落。
4. **无真实善本扫描样本**：测试仅 line.png（小行图）+ youlan scan.jpg（手卷，非善本竖排）。**真实善本扫描（如宋本四书页图）是后续开发/测试必需**——建议准备一部公版善本扫描（pdf/jpg）入 `input_data/pointcheck/<work>/shanben/`。
5. **pdf→图依赖 poppler**：node 无纯 JS 的 pdf 渲染（pdf-lib 只操纵不渲染），pdftoppm 是最简依赖。
