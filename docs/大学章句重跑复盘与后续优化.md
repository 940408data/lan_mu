### 1.1 清洗收益的严格 A/B 结果

不能只用“字级异文总数”衡量清洗：69 条异体是善本原刻字形与现代字形的差异，按设计应保留。以 P1.5 前的 0a61d97 结果为基线，本轮清洗后的变化如下：

| 指标 | 清洗前基线 | 清洗后（含现代本尾部刊记规则） | 变化 |
|---|---:|---:|---:|
| 现代本正文字符 | 8,724 | 8,500 | −224 |
| P3 对齐段 | 576 | 574 | −2 |
| exact / fuzzy | 530 / 40 | 538 / 33 | exact +8、fuzzy −7 |
| orphan | 6 | 3 | −3 |
| 非 orphan 的低分段（<0.8） | 5 | 1 | −4 |
| 字级异文 | 105（真异文36/异体69） | 98（真异文29/异体69） | −7；异体不变 |
| 夺衍换簇 | 33 | 21 | −12 |

其中 224 个被排除字符包括页眉、脚注、现代本校记，以及末页“大学章句毕／从政郎……校正”刊记。清洗前后异体始终为 69 条，说明“清洗”不会也不应把古今字形差异抹掉；本轮真正减少的是 7 条疑似版面/校记造成的真异文候选和 12 个簇。结论是：清洗有效，但收益主要体现在输入纯度与对齐稳定性，而不是把总数压到很低。

## 2. 本轮暴露的具体问题

### 2.1 网格判定的置信度契约不一致

`gridColumns` 的提示词只要求列数组，不要求整体 `conf`；通用 `review()` 却把“无 conf”当作低置信度，导致每页无谓升级到 qwen3.8-max。本轮前 6 页已出现 `conf=0.00 (覆校)`，修复路由后后续页面改为初校直出，日志显示 `conf=n/a`。

已修复：结构合法时接受初校；JSON 为空或列结构不完整才升级覆校。后续应把视觉任务响应统一成带 `schemaVersion`、`confidence`、`issues[]` 的契约，避免不同提示词依赖同一置信度字段。

### 2.2 非标准页形态没有独立模型

M3 目前假定 16×15 网格，p2、p6、p10、p37–40 的列数不足 16 时仍能产出结果，但无法区分“半叶/题跋/缺列/模型漏列”。建议：

1. M0 为每页登记 `pageShape`（full、half、title、colophon、partial）。
2. `judge-grid` 先做页形态分类，再按形态选择列数与经注规则。
3. 质量报告增加 `gridCoverage`、`unexpectedColumnCount`，非标准页自动进入人工队列。

### 2.3 P4.5 orphan 回修缺少可验证定位

本轮 3 处“善本底本误”均有视觉结论，但 `apply-basefix.js` 的安全守卫全部拒绝自动回修：

- c4：应补「又日新之不可略有間斷也」，六字前邻在当前 OCR 中不精确命中。
- c11：当前 p20 已经存在「其意」，判定为对齐 orphan 噪声，跳过是正确的。
- c19：长锚点混入注文 OCR，无法唯一定位；强行替换会有误删正文风险。

这说明“视觉判定正确”不等于“可安全回灌”。下一步应增加 bbox/列号溯源，或让 P4.5 输出 `sbPageUsed + sbColumn + sbBefore/After`，回修前要求唯一列级命中；无法唯一命中就保留人工，不自动猜测。

### 2.4 P3 对齐仍有结构性 blocker

清洗后仍有 3 个现代本句段 orphan、1 个低于 0.8 的段和 2 处相邻善本文字重叠。末页刊记已从正文剥离，但这些结构性对齐风险仍然存在；它们不是 P5 可以消化的异文，应在 P3 质量闸先处理：

- 对 orphan 增加“现代本重复句/跨页句/善本漏录候选”分类；
- 对相邻重叠增加跨页边界和页形态特判；
- 低分段进入视觉定位队列，不进入自动校书官裁决。

### 2.5 P5 延迟和可恢复性

本轮 P5 共有 32 条、每条并行询问四位校书官；增量文件可恢复，但旧裁决迁移时曾发现“无新目标则不落盘”的问题，已修复为迁移后立即写回，避免 v99/v100 这类过期条目再次混入出具。建议：

- 按证据类型分批：先处理真异文，再处理簇级真异文；
- 对相同 `(善本,现代本,所在句)` 做意见缓存；
- 增加单条超时、重试上限和失败队列，避免一个请求拖住全链；
- 结果继续写入 M2 hash，禁止跨底本复用。

## 3. 当前结论与下一步

大学已完成一次“新 M2 底本 → M3 → P3/P4 → P4.5 → P5 → P6”的真实闭环，但仍是 `draft`：

1. c4、c19 需要人工在精校台确认是否回修；c11 暂不回修。
2. 若发生底本回修，必须重新跑 M3、P3、P4、P4.5、P5、P6。
3. 处理 orphan/低分/重叠后，才能评估是否进入 M6 `build-works`。
4. 中庸应复用本轮修复后的网格置信度路由与页形态检查，再开始全页重跑。

## 4. 可复现入口

```bash
node collation/tools/verify-v2.js 大学章句 --conc=1
node collation/tools/pipeline.js 大学章句 --pages=2-40 --conc=3

```

`pipeline.js` 会锁定 M2 指纹；任何旧 grid、旧簇核验或旧裁决都会被拒绝或清空，不应手工绕过。
