# 校勘优化方案

> 承接《校勘异文讨论》——当前善本点校本质量瓶颈在**上游**（OCR 底本、经注分栏、对齐噪音），而非"异文悬置多"。本方案给出把善本点校本打磨到**可进兰木 songke 引擎**的优化路线。

## 0. 目标与验收

**目标**：产出一份善本点校本，满足——
1. 底本文字可靠（OCR 误读经视觉复核纠正，错字率显著下降）；
2. 经注分栏正确（经 j 大字 / 注 z 小字区分，合朱子章句体例）；
3. 异文清单干净（无错位/异体/版式噪音，只剩真学术异文）；
4. 真学术异文全部经校书官裁决，悬置者入人工复核闭环；
5. 可转写为 `works/<id>/text.yaml`（`sections[].blocks[]{type:j|z,text}`），被兰木引擎消费。

**验收**：`npm run validate` 字数基准对齐；善本点校本抽查若干页与现代本、扫描图三方一致；校勘记异文条数较当前（大学 274 / 中庸 653）大幅下降且剩余皆为真异文。

## 1. 现状瓶颈（上游）

| 瓶颈 | 表现 | 根因 |
|---|---|---|
| 底本错字 | 慘/僉、曰/日、丁/子 等 OCR 误读进了善本正文 | input_data 旧 OCR（疑 tesseract 类）质量参差 |
| 经注混排 | 善本点校本经注连排，无大小字区分 | flat OCR md 丢失字高；旧 OCR 无 bbox |
| 对齐噪音 | 夺/衍 157 + 真异文里错位 26、异体 ~15 | 页中书题未剥离、朱子章句强锚未用、异体表不全 |

## 2. 优化方案

### A. 上游底本：视觉重 OCR 与旧 OCR 互证（P1 重做）

**原则**（用户指正）：不单一依赖 qwen3.7-plus 视觉，**两路互证**。

1. 用 `ocrPage`（初校，关思考，快）逐页视觉重 OCR 善本 → 新 OCR 文本；
2. 与 input_data 旧 OCR **逐字比对**（编辑距离对齐）：
   - 两路一致 → 采信；
   - 两路相异 → 标记，升**覆校**（qwen3.8-max，开思考）对该字/该区域仲裁；
   - 仍疑 → 入 flags 人工。
3. 产出干净善本底本 `data/<书>/shanben-v2.json`（页×列×字，带两路一致性标记）。

> 也可直接复用 `/root/guji_ocr/ocr_dianjiao_original_only.py`（多线程+多 key+断点续传+OpenCC）批量重 OCR，再与旧 OCR 互证。

### B. 第三层：清对齐噪音（P3/P4 加固）

1. **剥离现代本页中书题/页码**（治 v5 类假夺）：对齐预处理时识别"栏间书题/鱼尾/页码"行（短、与前后文不连、含书名），剥出另存，不作正文句。
2. **朱子章句强锚点**：以「右經一章」「右傳之X章」「釋XX」等章节标记为硬锚，分段对齐，杜绝跨章滑动错位（治"所惡於上…"回文错位）。
3. **扩 VARIANT_MAP**：把实测冒出的善本古异体（頽/頹、夭/天、㓜/幼、爭/争、乗/乘、償/債、巳/已、已/己…）补入归一表，消掉"未归一异体"噪音。
4. **视觉复核 OCR 误字**：对互证后仍疑的字，`verifyChar`（初校读善本扫描页确认实字，conf 低升覆校）；实字≠OCR → 消解异文（如慘/僉）。

### C. 第一层：经注大小学批量判定（P2.5-jz）

1. 对善本**正文页**（跳过全大字的序页）逐页 `judgeJZ`（初校，**开思考**保精度），产 `jz.json`（页×列×j/z×字）。
2. conf < 0.7 的列升覆校复判。
3. 用 jz 结果给善本点校本**分栏**：经 j 大字、注 z 小字双行，合朱子体例 → 为转 `works` 的 `type:j|z` 做准备。
4. 与 §A 的干净底本交叉校验字数。

### D. 学术裁决：全量校书官 + 人工终裁（P5/P7）

1. 清完噪音后，对**剩余真学术异文**全量跑四校书官（不再只 6 条样本）——接 LLM（`DASHSCOPE_API_KEY` / `ANTHROPIC_API_KEY`）批量裁决。
2. 产出 resolved（定论入善本点校本夹注）/ suspended（暂拟 + 线索）。
3. **人工终裁**悬置项（当前大学 v82 二/一、中庸 v278 脩/修）：需核他本/石经（宋刻递修本章次、唐开成石经《礼记》、宋刻礼记单行本、《经典释文》），此步**归人**，不靠模型。
4. 人工结论回写 verdicts `human` 字段，重跑出本。

### E. 工程优化（速度/成本）

| 项 | 措施 |
|---|---|
| 并行 | 多线程 + 多 key 轮询（参考 guji_ocr 脚本 concurrency），118 页串行 ~数小时 → 并行 ~30–60min |
| 瘦身 | 裁裱边减像素 / dpi 130–150 平衡；纯 OCR 关思考（5.7× 提速），版面判定开思考 |
| 断点续传 | 进度文件记录已处理页，中断可续（参考 guji_ocr） |
| 成本闸 | reconfirm/jz 支持 `--limit` 与 dry-run；批量前先小样本验证 |
| 缓存 | 同页图渲染/调用缓存，多异文共享一页 |

### F. 进兰木引擎（P8 落地）

1. 干净善本底本 + jz 分栏 → 转写 `works/<id>/text.yaml`（`sections[].blocks[]{type:j|z,text}`）。
2. 填 `meta.expect`（chars/jChars/zChars）为校验基准；`npm run validate`。
3. `npm run build --work=<id> --only=html` 快速验证版面，再全量出图。
4. 现代本**不进 dist**（B 级自用，著作权隔离）。

## 3. 分阶段里程碑

| 阶段 | 内容 | 产出 | 依赖 |
|---|---|---|---|
| M1 | 清噪音（B：剥书题/强锚/扩异体表） | 异文清单去噪，大学 274→真异文数十条 | 纯代码，无需 API |
| M2 | 视觉重 OCR + 互证（A） | 干净善本底本 shanben-v2 | 需 API，并行 |
| M3 | 经注判定（C） | jz.json，点校本分栏 | 需 API |
| M4 | 全量校书官（D.1-2） | resolved/suspended 全覆盖 | 需 API |
| M5 | 人工终裁（D.3） | 悬置项定论 | **归人** |
| M6 | 进引擎（F） | works/daxue、works/zhongyong 善本底 | M1–M5 |

> 建议先做 M1（纯代码、零成本、立刻见效——先把 274/653 的噪音压下去，看清真异文到底有几条），再视效果投入 M2–M4 的 API 成本。

## 4. 风险与边界

- **视觉模型非万能**：初校（qwen3.7-plus）读图有误差，故坚持"两路互证 + 覆校仲裁 + 人工兜底"，不单一依赖。
- **学术裁决归人**：模型给倾向与理据，但版本源流、石经他本的最终裁断须人；悬置项不强行定论。
- **双本法理隔离不变**：善本点校本（公开）与现代本（自用）两条线始终分开，现代本整理成果不进 dist/不外传。
