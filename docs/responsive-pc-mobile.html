一如何区分 PC 与移动端

不在 JS 层做设备嗅探——全仓无 matchMedia / ontouchstart / maxTouchPoints / navigator.userAgent 之类运行时判断。区分完全由 CSS @media 断点承担，共三处：

文件断点命中后的改动
src/viewer/viewer.css:226 max-width:860px 手卷查看器：顶栏压至 64px、隐藏次要信息（.mark/.facts/.tt p/.btn.txt）、进度条缩短、hud 内移
src/viewer/songke.css:181 max-width:820px 宋版查看器：--u 由 26px → 15px，整版字格等比缩小
src/site/site.css:345 max-width:820px 站点页：书影缩小、.fan 专题卡一列→两列、搜索结果省略副标

viewport meta 全局统一，见 src/render/html.js:158、src/render/html-songke.js:137、src/site/render.js:49：

<!-- width=device-width + initial-scale=1，未禁缩放（无 user-scalable=no）-->
<meta name="viewport" content="width=device-width, initial-scale=1">

手卷断点取 860（比别处 820 大），因顶栏按钮多、更早需要让位。移动端用户可双指自由缩放整页。

二自适应的四层机制

没有 React/Vue 等框架，是原生 HTML/CSS/JS + 构建期烘焙（src/render/html.js 烘焙进 HTML）。自适应靠四层显式机制，非框架魔法：

① 流式单位（站点页为主）

src/site/site.css 大量用 rem + max-width 居中：.cabinet 限 1060px（:88）、.seek 限 34rem（:54）、书影 .tome 8rem×11.2rem（:98）。rem 随根字号、随断点缩放，flex-wrap 自动换行回流。

另有一处无断点自适应——min() 让 PC 下取 400px、窄屏自动留 32px 边距，无需媒体查询：

/* src/viewer/viewer.css:215 */
.panel{width:min(400px,calc(100vw - 32px));max-height:calc(100vh - 110px)}

② 视口单位 + 数据驱动固定像素（查看器）

手卷 viewer.css 用 100vh/100vw 撑视口（.viewer height:calc(100vh - 76px)，:183），但卷面几何 --paper-w/--wrap-h 是固定 px，由 meta.yaml 注入——这是「逐字节可复现保真」的硬约束，npm run verify 守门。

宋版 songke.css 则以一个根变量 --u（大字格）派生全部尺寸，移动端只需调 --u 一处，整版等比缩：

/* src/viewer/songke.css:3-11 */
--u: 26px;                     /* 大字格：一格一字 */
--col-h: calc(var(--u) * 16);   /* 半葉高：十六字 */
--col-w: calc(var(--u) * 1.40);  /* 行宽 */
--su:    calc(var(--col-h) / 25); /* 小字格 */

③ Pointer Events 统一输入（关键）

手卷查看器 src/viewer/viewer.js:66-71 用 Pointer Events（pointerdown/pointermove/pointerup + setPointerCapture）做横向拖卷——鼠标、手指、触笔同一套代码，无须分别写 mousedown/touchstart。再补 wheel（PC 滚轮纵向→横向，:71）与键盘 ArrowLeft/Right（:76-77）。移动端无滚轮/键盘也无所谓，手指 pointer 拖动即可。

/* src/viewer/viewer.js:66-71 */
viewer.addEventListener('pointerdown',e=>{if(e.button)return;down=true;sx=e.clientX;sl=viewer.scrollLeft;
  viewer.setPointerCapture(e.pointerId);viewer.classList.add('drag');});
viewer.addEventListener('pointermove',e=>{if(down)viewer.scrollLeft=sl-(e.clientX-sx);});
viewer.addEventListener('pointerup',()=>{down=false;viewer.classList.remove('drag');});
viewer.addEventListener('wheel',e=>{/* 纵滚轮转横向，PC 专属 */
  if(Math.abs(e.deltaY)>Math.abs(e.deltaX)){viewer.scrollLeft+=e.deltaY;e.preventDefault();}},
  {passive:false});

宋版是翻页式（btnPrev/btnNext + scrollIntoView，songke.js:211-212），click 原生通用；键盘翻页（songke.js:221-224）是 PC 加分项。

④ 打印态与无障碍

@media print（viewer.css:235）隐去界面、长卷铺平为单页——为 PDF 输出。另有 prefers-reduced-motion 三处（viewer.css:232、songke.css:182、site.css:357-358），关闭动画以照顾前庭敏感用户。

四移动端优化指南

架构本就为「窄屏隔离」设计：在 @media(max-width:820/860px) 块内加规则只影响窄屏，宽屏（PC）不进断点、零影响。Viewer 的 Pointer Events 已统一输入。可以放心做。

✓ 安全边界（只碰这些，PC 不受影响）
  • 在 @media(max-width:820px) / (max-width:860px) 块内新增规则——只命中窄屏
  • 调派生根变量：宋版缩放走 --u、手卷缩放走 --zoom（viewer.js 的 fit() 已按视口高度算 zoom，:80-85）
  • 用 min()/max()/clamp() 做无断点自适应（仿 .panel width:min(...)）
⚠ 红线（碰了会波及 PC 或破坏保真）
  • 勿改断点之外的全局规则——宽屏会跟着变
  • 勿动 --paper-w / --wrap-h 等手卷几何量——这是 verify 逐字节保真基准，动则幽兰回归报红
  • 勿逐个改宋版派生量（--col-h 等），只改 --u
  • 勿加 user-scalable=no 禁缩放——剥夺无障碍放大
▸ 可行的优化方向（均在断点内实施）
  • 顶栏按钮组挤压：860px 下手卷顶栏按钮偏挤，可分组折叠为「⋯」溢出菜单
  • 横向拖卷惯性：移动端 pointerup 后加 momentum 滑行（现仅跟手，松手即停）
  • .panel 抽屉化：窄屏把浮层「关于」面板改为底部抽屉，避免遮挡卷面
  • 双指捏合缩放：现只有按钮 ±（viewer.js:23），可加 gesturechange/pointer 双指识别直接改 --zoom
  • 宋版手势翻页：现靠按钮 + 键盘，可加左右滑动手势调 go(±1)

改完务必：npm run verify（幽兰逐字节保真守门）＋截图目检。目检避坑见 CLAUDE.md——用系统 Chrome（chromium.launch({channel:'chrome'})）、元素级截图（page.$('.sel').screenshot()）、勿 fullPage、勿把 PNG/dist/字体读进上下文。
