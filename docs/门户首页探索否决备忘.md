## 二、第一輪 wen/zhi 的否決病因（已確證）

- **結果**：用戶審 wen / zhi 後反饋「效果都不好」，兩 worktree 刪、兩分支強刪。
- **病因**：兩端對比（大眾偏直白亮底 / 專業偏密集暗底）**形式先行、氣質缺位**——各執一端反而都不「含蓄」。綱領精神是「文質彬彬、由文入質、不強施」，落實到視覺應是**含蓄、克制、典雅**（用戶原話），而非把「文」「質」拆成兩個頁面對壘。
- **收斂結論**：改為單一融合文質首頁（portal-dianya），氣質統一而非兩端對壘。此收斂方向被第二輪三版繼承，但三版最終仍被否（見 §三）。

## 三、第二輪 dianya/ye/su 的探索與否決

### 3.1 收斂發現（客觀事實，值得記住）

三版由兩個互不知情的會話獨立給出，卻收斂到同一設計語言——**宋版書葉**（素紙底、魚尾版心、文右質左、豎排、三色、無動效）。§二的教訓「先立氣質主線再動手」在此得到驗證：兩會話獨立得到的主線一致。但「主線一致」不等於「可採用」——三版仍被否。

### 3.2 三版客觀設計（保留供後續參照）

- **dianya**：宋槧半葉雙欄 + 版心魚尾——右半葉「四時之樂」（蘭亭/赤壁/山海/湖心）、左半葉「四書之味」（大學/中庸/論語/孟子），版心天然分隔文質。引首「蘭木」大字 + 朱印 + 「文質彬彬，然後君子」題款。產物 8.9KB 自包含。氣質三筆：含蓄（弱化板塊名為「之樂/之味」短語、極淡小字置欄底）、克制（三色無動效、匡線 0.6–1.5px）、典雅（素紙底、豎排、單魚尾版心、大量留白）。**最大氣質差異**：全頁素紙底，棄用 site.css 暗案底（`#221d18`）。
- **ye**：整葉細墨框一「葉」，界行欄線，版心魚尾；右半大字列「四時幽賞」+ 春夏秋冬四小注列，左半「四書涵泳」+ 學庸論孟。保留原語作大字列（與 dianya 弱化板塊名互為對照）。產物 6.2KB。
- **su**：唯一減法方向——無框無線零裝飾，十之八九留白；直排大字「四時幽賞」+ 四列疏落小注，四書更淡一檔（墨色按透明度分五檔）；角落「蘭木」落款 + 唯一微朱小印。全程無 JS 無動畫。產物 5.3KB。

### 3.3 否決判定

2026-08-13 用戶審 dianya/ye/su 三版後判定均「不合适」，三 worktree 刪、三分支強刪（共 11 筆提交丟棄）、預覽進程停、產物不存在。

### 3.4 病因（事後推斷，非用戶原話）

用戶未給出單一可述病因，判定為綜合直覺。以下為基於三版客觀設計特徵的事後推斷，**定奪須以用戶為準**：

- **① 門戶接引力可能不足**：門戶首頁有功能義務（檢索、部類速達、書影導向、多卷直達），三版皆偏「一幀書葉的靜態美」，藏書首頁原有的檢索框、部類錨點、瓷青書影列被弱化或去掉，作「門戶」的接引力可能不足。
- **② 全站底色割裂未決**：三版皆素紙底，與現有藏書首頁 / 目錄葉 / 書庫的暗案底對立。一旦上位，須全站改底色基調，此「必決」問題自第一輪起懸而未決，成本與風險大。
- **③ 路徑本身可商榷**：五版皆「另起新首頁」，而現有「藏書」首頁已是有結構、有功能的門戶。「含蓄克制典雅」或應在藏書首頁之上收斂改氣質，而非反覆另起。五版皆廢，根因或在此路徑分叉未先確認。
- **④ 方向已窄**：三版獨立收斂到同一語言，說明此方向探索空間已窄，再做恐仍是同一變奏。

## 四、給後續 Agent 的教訓（核心）

1. **審美探索數量≠質量**：與其兩端對比（wen/zhi），不如先把綱領精神翻譯成一條明確氣質主線再動手。
2. **「含蓄」要落在具體設計語言**：色少、飾少、留白多、細線、無動效——不能只停在理念層。
3. **探索性分支隨時可棄**：小步提交、隨時可刪；文檔引用分支 / 提交時須標注其生命週期狀態（本檔已標「已刪」）。
4. **【本輪新增】反覆另起新首頁是高成本路徑**：兩輪五版皆廢，根因疑似未先確認「改現有首頁氣質 vs 另立新首頁」這一路徑分叉。下次動手前須先與用戶確認此分叉。
5. **【本輪新增】門戶頁有功能義務**：接引、檢索、導向書是首頁本分，氣質探索不能以犧牲門戶功能為代價。三版皆弱化 / 去掉了藏書首頁的檢索 / 書影 / 部類速達——任何「典雅」候選都須先回答「門戶功能怎麼安放」。

## 附：技術避坑（與審美否決無關，工作流經驗仍有效）

- **6MiB 請求體上限**：勿 Read dist 產物 / 字體二進制 / 截圖 PNG；`grep -n` 定位 + 局部 Read offset/limit。
- **worktree cwd 陷阱**：subagent Bash cwd 默認主倉庫，須 `cd <worktree> &&` 前綴或 `git -C`，先 `pwd` 確認。
- **node_modules 不共享**：worktree 無 node_modules，`ln -s /root/lan_mu/node_modules node_modules` 復用（勿 npm install）。軟鏈不被 `.gitignore` 的目錄模式匹配，須顯式 `git add` 指定目標文件，否則易誤提交軟鏈。
- **多會話端口互擾**：兩會話同時起 serve，端口層層順延。實際監聽口徑以 `ss -ltnp` / `pgrep` + `/proc/<pid>/cwd` 核實，勿信命令裡傳的端口號。
- **worktree 字體源兩段式**：無字源時 build 照常（子集跳過、落系統回退棧）；真楷宋預覽與完整小字庫須自主倉拷 A 級字源至 worktree 的 `src/fonts/src/`（gitignore 位，不入庫）。
- **worktree 全鏈路預覽**：新 worktree 的 dist 只有站點頁，作品頁鏈會 404；須 `node tools/cli.js build --only=html` 全量補作品 HTML。
- **雙 agent 零衝突要訣**：各自只改五處（render 新增函數 + home 配置塊 + build 接線 + serve 路由 + 獨立 css），共享 `head()` 一字不動、site.css 不碰。
- **pre-commit verify 觸發判定**：hook 正則 `^(src/(core|render|fonts|viewer)/|works/youlan/|css/)` 匹配 `src/render/`，門戶改動在 `src/site/` 不匹配，故只跑 validate、verify 不觸發（門戶改動不碰幽蘭，符合 PORTAL.md §5.4）。
