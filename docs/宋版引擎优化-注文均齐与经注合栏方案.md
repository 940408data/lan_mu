# 宋版引擎优化：注文双行均齐 · 经注合栏方案

分支：`songban_zhushi_binglie`（基于 `dev`）
范围：`src/core/typeset-songke.js`、`src/render/html-songke.js`、`src/viewer/songke.js`、各作品 `meta.yaml`（expect / colophon）

---

## 一、背景与现状

宋版善刻引擎现行成法（`typeset-songke.js` 文件头所述）：

- **纯经列**：经文大字单行，每列至多 `bigPerCol`（16）字；
- **纯注列**：注文小字双行（右行先、左行次），每行至多 `subPerCol` 字（疏朗 20 / 雅正 22 / 宋槧 25）；
- 经列与注列**互不共列**：注文必另起新列，逐行贪心填满——右行先满，再填左行。

由此产生两个观感问题：

1. **注尾单行孤悬**：注文块尾列常出现「右行满长、左行空白」或两行长短悬殊。
   实例：《論語集注》卷七（lunyu7）子路「樊遲請學稼」章注末段
   `失愈遠矣故復言之使知前所言者意有在也`（18 字），今法整段置于右行，左行全空。
2. **短经之后注另起列**：经文若只占半列，注文却另起全新之列，经注割裂、留白破碎。

## 二、需求

1. **注文双行（双列）必须并行均齐**：一列内右行与左行字数**完全相同或仅差一字**。
   事先计算注文总长与可用空间，若有剩余空间，按均齐分配。上例应变为：

   ```
   失愈遠矣故復言之使    （右行 9 字）
   知前所言者意有在也    （左行 9 字）
   ```

2. **经注合栏**：经文结束后，注文**不必完全新起列**——注在经末之后空**两个小字符**起写；
   若本列剩余空间不够，则注文仍于新列起。

## 三、格制数学

排版以 `UNIT = 400` 为列高总量：

- 大字高 `bigH = UNIT / bigPerCol = 25`；
- 小字高 `smallH = UNIT / subPerCol`：疏朗 20 / 雅正 ≈18.18 / 宋槧 16；
- 一列可容小字符数（每行）= `subPerCol`。

设经文占本列 `n` 个大字（0 ≤ n ≤ 16），新增配置项（`conf`，可由 `meta.songke` 覆写）：

| 配置 | 默认 | 含义 |
|---|---|---|
| `minNoteFit` | 2 | 合栏起注时，每行最少须容下的小字数（不足则新起列） |

**注起始位置与纯注列网格对齐**：

```
g = ceil(n × bigH / smallH)  // 注起始行号（0-based）
cap = subPerCol - g          // 本列每行剩余容量
```

即：大字占 n 个，注从第 g 行小字位置开始（与纯注列第 g 行对齐），本列每行可再容 `cap` 字。

三版数值表（`cap ≥ minNoteFit = 2` 方可合栏）：

| 经占大字 n | 疏朗 (20) | 雅正 (22) | 宋槧 (25) |
|---|---|---|---|
| 11 | 5 ✓ | 5 ✓ | 6 ✓ |
| 12 | 4 ✓ | 4 ✓ | 5 ✓ |
| 13 | 2 ✓ | 3 ✓ | 3 ✓ |
| 14 | 1 ✗ | 1 ✗ | 2 ✓ |
| 15–16 |  | ✗ | ✗ |

即：经占约四分之三列以上时，注自然新起列；短经则注随经下，衔接紧凑。

## 四、排版算法（重写 `layout()`）

区块序列仍按原顺序处理，列模型扩展为 `{ big, subs: [[右行],[左行]], g }`，
`g` 为注起始处距大字末位的**小字符空格数**（纯注列 / 续注列为 0，合栏列为 `noteGap`）。

### 经块（j）——不变

每章另起新列，逐列满填 16 字（「遇章別行」保留）。

### 注块（z）——新法

**1. 定锚（合栏判断）**：

- 若**前一区块为 j** 且末列有大字，计算 `g = ceil(n × bigH / smallH)` 与 `cap = subPerCol - g`：
  - `cap ≥ minNoteFit` → 注即于该列续写，`g` 为注起始行号，本列每行容量 `C = cap`；
  - 否则 → 新起一列，`g = 0`，`C = subPerCol`；
- 若前无列、或前一区块为 z（连续注块）→ 一律新起列（`g = 0`）。
  （现存作品每章均为 1j+1z，无实际影响，保留此限以免注注相接生歧。）

**2. 填注（均齐分配）**：设注余 `L` 字，本列每行容量 `C`：

- 若 `L ≤ 2C`（注尽于本列）：右行 `⌈L/2⌉` 字、左行 `⌊L/2⌋` 字；**不再先满右行**。
- 若 `L > 2C`：本列满填 `C / C`，余 `L − 2C` 转入新列（`g = 0, C = subPerCol`），
  直至末列按上一条均齐收束。

由此**每一注列皆满足「两行相同或差一字」**：满列自是 `C/C`，末列 `⌈r/2⌉/⌊r/2⌋`。

### 边界情形

| 情形 | 处理 |
|---|---|
| 经恰满列（n=16） | `cap < 0`，注新起列 |
| 注长仅 1 字 | 右 1 左 0（差一之限，不可避免） |
| 注长恰为 2C 整数倍 | 末列满行 `C/C` |
| L 为奇数 | 右行多一字（右行先读） |
| 卷界 | 不受影响：新卷仍补空列至叶界（卷界处理在 `buildVariant`，逐版独立重排） |
| 三版各自成列 | 均齐与合栏计算在 `buildVariant` 内按各版 `subPerCol` 分别执行 |

### 示例验证

lunyu7 夫樊遲章注末 18 字：

- 旧法：右行 18、左行 0；
- 新法：`⌈18/2⌉ / ⌊18/2⌋ = 9 / 9`，即
  `失愈遠矣故復言之使` / `知前所言者意有在也`。✓

5. **draft 截断**：草稿卷仅示首叶（前两半叶）之制不受影响。

## 八、假设与取舍

- 「两个字符」释为**两个小字符高**（`noteGap` 可调）；若欲两大字高，改默认值即可，算法不变。
- 均齐以**列内自足**为则，不做跨列腾挪（如故意留白以求全局匀整）：贪心满填 + 末列均分已保证每列两行差 ≤ 1，且实现简单、结果确定。
- 注注相接仍另起列：现存数据皆为 1j+1z 章制，此限无实际影响，免生歧义。
- 宋版骨架（半叶八行、行十六字、列宽、大字规格）不动；三版叶数变化属预期。
- 实施顺序：核心算法 → 渲染两处 → expect 重算 → colophon 文案 → 预览微调。
