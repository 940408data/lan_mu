## 三、需优化 / 整改项（按优先级）

### 1. 经史子集页缺自身题署（中，建议整改）

`renderSanzang` 复用首页 `HOME_MASTHEAD`（`src/site/render.js:300`），卷首仍是「蘭木 / 聲微志遠，此弄宜緩」——**页面上看不到「經史子集選編」任何字样**（仅 `<title>` 有）。从首页底端「古典 · 經史子集選編 →」点入后，落地页与首页卷首逐字相同，仅靠页签数量（2→4）区分，访客难以感知已进入「深层藏」。

对照：书库页有独立题署「書 庫 / 全帙一覽」（`renderShuku` 用 `masthead()`）。此乃 0327「原样迁存」的合理遗留——当时它是首页，身份变了题署未随。

**建议**：sanzang 页改独立题署，如「經史子集 / 選編」，一行配置即可，同时亮明分层身份。

### 2. 首页「专题推荐」与文质页签同页重复（中，需用户定夺）

现状首页自上而下：文质页签（四时四部 + 四书四部）→ 专题推荐两卡（仍是四时幽赏 + 四书涵泳）→ 古典入口。专题卡链去的 `/topics/` 页内容与页签面板**完全相同**（同样四部书影），同页两层零差异重复。

此即 v1 用户指认「部类页签与四书板块同源同形，没有意义」问题的变体。v2 定案恢复专题卡的初衷是「将来高濂配套等专题内容需要展位」——但展位对象（新专题）尚不存在。选项：

- a) 保留，接受暂时重复（为新专题留位）；
- b) 暂时撤下，待高濂《四时幽赏录》等新专题就位再回归；
- c) 专题区改放预告型内容（如「四時幽賞錄 · 輔文待補」占位），与页签功能区分。

### 3. 书库与选编「双深层入口」角色重叠（中，至少文案厘清）

导航「書庫」（真书全帙按 `meta.category` 分组）与底端「古典 · 經史子集選編」（部类编选 + 虚拟占位）均按部类组织，普通访客难辨差异。纲领中「图书馆深层藏」本是一个出口，现状两个。短期可借第 1 条让选编页亮明「選編」身份形成分工：**书库 = 目录学全帙，选编 = 荐读编选**；远期选编页真书渐多后再议是否合并。

### 4. 文档漂移（低-中，应同步）

- **CLAUDE.md「站点页」节过时**：仍写「卷影：`panels.js` 构建期从四时手卷整卷 PNG 的右起卷首文字区裁 560px 竖条」——`panels.js` 现已是拷贝 `src/site/assets/topics/` 手工备图（128×179），裁切管线在 `b9e6992` 被图像资产取代（旧管线留存于 git 历史 `e9990d4`，可捞回）。首页「四时手卷**卷影屏**」描述同样过时（现为立式瓷青画板接四时图资产）。
- **纲领 §七「现状底子」过时**：`TABS` 仍记「儒家經典/佛家/道家三页签」（line 169）；§三.1 仍写「四时/四书是专题推荐区（TOPICS），非页签」。纲领自称「活纲领」，宜加校准标注而非改写历史段落。

### 5. 选编页默认页签「经选」全为虚拟（低，内容排期问题）

无 JS 或首访时选编页首屏为 4 部「敬请期待」，无一真书（真书尽在子选）。经史子集之序不可动，解法唯有**尽快校录一部经部真书**（如《诗经》选篇）充实首选页签。属内容排期建议，非布局问题。

### 6. 小处（低）

- 检索框 placeholder「檢書名 · 篇名」未提卷次，索引实覆盖卷次（`render.js:184`）——可改「檢書名 · 卷次 · 篇名」。
- 首页无 `<meta name="description">`，分享/SEO 无摘要。
- 选编页、书库页无「回蘭木藏書」底链（专题/校书官/敬请期待页有）——靠顶部「蘭木」回，一致性可接受，仅提示。
