## 1. 起始输入（一切开始之前）

| 输入 | 路径 | 说明 |
|---|---|---|
| 善本扫描 | `input_data/<书>/当涂郡本_pdf/page_XXXX.pdf` | 公开善本分页 PDF（gitignored，运行期读取） |
| 善本旧 OCR | `input_data/<书>/当涂郡本_ocr/page_XXXX.md` | 外部 OCR 产物，每页一 md |
| 现代本扫描 | `input_data/<书>/儒藏本_pdf/page_XXXX.pdf` | 现代点校本分页 PDF |
| 现代本 OCR | `input_data/<书>/儒藏本_ocr/page_XXXX.md` | 同上 |
| 版本登记 | `collation/config/editions.yaml` | editions（id/role/level/ocrDir/pdfDir）+ works（书名→两版本映射） |
| 视觉配置 | `collation/config/vision.yaml` | 初校(qwen3.7-plus)/覆校(qwen3.8-max)、阈值 0.7、思考开关、dpi、keyEnv |
| 校书官画像 | `collation/officers/{liu-xiang,jie-xian,dai-zhen,ji-yun}.md` | 四官 system prompt，Node LLM 与 Claude Agent 共用 |
| 既有兰木作品 | `works/<id>/`（可选） | 两个用途：verify-jz 的 ground truth 核验基准；build-works 的 meta 模板 |

**数据落盘约定**：一切中间产物写 `collation/data/<书>/`，最终文本写 `collation/data/<书>/output/`（经 `docs/collation-data` 软链挂 docsify）。

## 2. 逐阶段详解

### P0 装载 — `src/io.js`
- **做什么**：读 editions.yaml + 两本 OCR 页 → 内存 Edition 对象 `{id, role, level, pages:[{n, lines, raw, isCover}]}`；登记 PDF 页数。
- **产物**：无落盘（内存）。封面页自动标记 isCover。

### M0 版面抽样 — `src/vision.js layoutProbe()`
- **做什么**：视觉 Agent 抽样 3–5 页善本，只总结**版面物理结构**：几列几行、每格一字还是双行夹注、顶格/退格规则、版心鱼尾书题位置。**每书必做，每书不同**。
- **产物**：⚠ **当前只在会话内记录，未落盘**（缺口②）。当涂本结论：16列×15行、每格一字、无双行夹注、顶格经/退格注。
- **质量闸**：抽样结论须能解释正文的全部列起始形态。

### M2 互证干净底本（三工具一循环，仅善本侧）
- **M2a `tools/recollate.js`**：渲染善本页 → 视觉重 OCR（关思考，快 5.7×）→ 与旧 OCR 逐字编辑距离比对 → `recollate-<起>-<止>.json`（每页 agree 一致率、diffs、visText）。**闸：平均一致率 ≥90%**，过低查版面/OCR 质量。大学实测 92.9%。
- **M2b `tools/build-v2.js`**：两路对齐后规则仲裁（一致采信 / 视觉缺字采旧 / 视觉多字舍 / 异体存善本原刻字形 / 真异→暂采旧+列待覆校）→ `shanben-v2.json` + `pending-verify.json`。**对齐用归一字、输出用原刻字形**——善本古异体不丢。
- **M2c `tools/verify-v2.js`**：pending 按页分组渲染扫描，verifyChars 批量问「实印何字」（初校开思考，conf<0.7 升覆校）→ `verify-report.json`（+ `shanben-v2-final.json` 中间态）。
- **收尾**：**再跑一次 build-v2** 应用 verify-report → `shanben-v2.json` 终态。**align.js 读的就是这份**（优先于旧 OCR）。大学实测纠正旧 OCR 误读 40 处。

### M3 版面判定经注（版面结构先行）
- **M3a `tools/judge-grid.js`**：逐页 gridColumns（列级：起始顶格/退格 + 列文字）→ 规则判经注（顶格=经 j、退格=注 z）→ `grid.json`。断点续传、并行、开思考。
- **M3b `tools/verify-jz.js`**：以既有 works 的 text.yaml 为 ground truth 核验判定准确率（大学 91.7%）。**只核验、不反哺**（否则失去通用性）。
- **M3c `tools/build-songke.js`**：grid.json → 经注分栏 `output/善本点校本-分栏.md`（大学 129–134 blocks）。

### P3 对齐 — `src/align.js`
- **做什么**：善本逐字 token（带页/列溯源；优先 shanben-v2.json）× 现代本句子，句锚点 + 编辑距离对齐。异体表 VARIANT_MAP **仅用于匹配归一，不改正文**；剥页中书题/内联校记；朱子章句强锚（右傳之/右經一章/右第X章）。
- **产物**：`aligned.json`（段级：segId/score/orphan/现代句/现代页/善本串）。`--step=align` 单跑。

### P4 对校 — `src/diff.js`
- **做什么**：对齐段平坦化为**字级**异文，分类：异体（归一合、形异）/ 真异文（两本各通）/ ocr疑（善本独异形近）/ 夺（善本无）/ 衍（善本多）。
- **产物**：`diffs.json`。大学 243 条 = 异体60 + 真异文49 + 夺47 + 衍87。
- **⚠ 结构性问题**：夺/衍把「注文措辞不同、OCR 跳行、页眉残留」炸成逐字行（如「之聖而不得君師之位」一处错位 = 10 行），既虚增体量又全部挂「待裁」无人认领——**这是缺口①的根源**。

### P5 校书官 — `src/officer.js`
- **做什么**：对**真异文 + ocr疑**逐条：四官（刘向/解缙/戴震/纪昀）并行各陈意见 → 陈列 → 出结论。≥3 官同采且平均置信 ≥0.6 → resolved，否则 suspended（暂拟+线索）。增量保存、断点续传。
- **产物**：`verdicts.json`（diffId/type/两侧字/verdict/adopt/tentative/opinions[]）。大学 49 条：resolved 29 / suspended 20。
- **未覆盖**：夺/衍（见缺口①）。

### P6/P7 出具与人工 — `src/export.js`
- **产物**：`output/善本点校本.md`（公开，A 级）、`output/现代本.md`（自用，B 级，不入 dist）、`output/校勘记.md`、`flags.yaml`（悬置 + ocr疑待办）、三份 JSON 回写。
- **人工回路**：flags → 核他本/石经 → 回写 verdicts.json `human` 字段 → `--step=export` 重出吸收。

### M6 进引擎 — `tools/build-works.js`
- **做什么**：grid.json → `works/<新id>/` 四件套（text.yaml 经注分栏 + meta 借 --base 模板 + seals/ornaments）。善本底独立新作品，不动通行本。
- **验证**：`npm run build -- --work=<新id> --only=html`。大学产物 `works/daxue-songben` 已过。

## 5. 已识别缺口与重构方案（待审批）

### 缺口①（核心）：校勘记应在流程内产生，夺/衍需正式核验环节
**问题**：夺/衍字级炸开、无核验、无裁决，校勘记靠事后补丁修正——流程倒置。
**方案（P4.5 正式化，四改动联动）**：
1. **diff.js 原生簇级输出**：同段内相邻（间隔 ≤2 同字）夺/衍归并为簇级条目（夺簇/衍簇/换簇=短语级异文），自带前后锚点与双侧页码；字级仅保留异体/真异文/ocr疑。
2. **run.js 新增 verify 步骤**：簇级双侧视觉核验（善本页+现代本页同呈，如实照录实印）——规则类（书题/页眉/牌记）直接归类不动视觉；核验结论四分类：现代OCR误（剔除留痕）/ 善本底本误（**回修 shanben-v2 重跑对齐对校**）/ 真异文（入册待裁）/ 书题牌记（剔除留痕）。工具已备（`cluster-dy.js`/`verify-clusters.js`），并入为正式环节。
3. **officer 裁决范围扩大**：核验为真的夺/衍/换簇进入校书官（善本脱文补不补、衍文删不删，本是校勘裁决）——如「家齊而后」若确证善本脱文，须有结论而非挂「待裁」。
4. **export 按环节出处汇总**：校勘记每行带「发现（对校）/ 核验（引擎+置信）/ 裁决（校书官|规则|人工）」三段出处；噪声不删、移「已核验噪声」附录留痕。
**兼容性**：旧 verdicts.json 按 `(segId, shanben, xiandai, type)` 内容键迁移到新编号，已裁 49 条不重跑；只有新增真夺/衍/换簇送校书官（约十数条）。

### 缺口②：M0 版面结构未落盘
抽样结论（列×行、格字制、顶退格规则、抽样页、probe 原文）应写 `data/<书>/layout.json`，供 judge-grid 读参、供复审。

### 缺口③：底本文件命名皱褶
`shanben-v2-final.json` 是中间态但名字像终态；终态实为二跑 build-v2 后的 `shanben-v2.json`。统一为唯一终态文件名（或 verify-v2 直接回填 shanben-v2.json）。

### 缺口④：run.js 编排不完整
`--step=all` 现为 diff→officer→export，缺 verify；补为 align→diff→verify→officer→export 一条命令全链。

### 缺口⑤：中庸按新管线重跑
含 M0（先抽样定版面）→ M2 → M3 → P3–P6 真跑 → M6（zhongyong-songben）。即 task #15，等 ①–④ 定稿后执行，一次到位。

### 缺口⑥：人工精校环节薄弱 + 裁决形式化不足（参照 ops_dianjiao 升级）
**问题**：P7 仅 flags.yaml 手工回写，无 UI 无回灌机制；校书官裁决是「≥3 同采 & 均信≥0.6」粗规则，无证据分级、无底本优先、无「无硬证据改正文必悬」铁律。
**方案**（详见 `docs/人工精校台设计.md`，含与 ops_dianjiao 方案的全面对比）：
1. **P7 精校台**：单文件离线 HTML（键盘流 J/K/1-9/V/E、V 键展开双侧书影、候选字投影正体防简体落公开本）→ decisions.json → `--step=apply` 回灌 verdicts.json（verdict:'human'，机器意见原文保留可推翻）→ 重出定本。
2. **裁决规则升级**：证据四级（確證/旁證/推測/無證）× 角色权重 × 置信加权投票；底本优先 β=0.15；悬置三规则（首选占比 <0.55 / 首选次选差 <0.18 / 改正文而无確證旁證）。
3. **限权硬约束**：officers/*.md 补「解缙绝不杜撰书证、纪昀不引新证只裁断」等。
**后续（P1/P2）**：异文分类细化（通假/避讳/倒文）、校勘记四库体例句、□不猜字规则、RuleSegmenter 独立句读+Jaccard 版权闸、契约测试——见对比文档 §2。

### 审批点
- ① 是结构性变更（diff/officer/export/run 四文件 + 编号迁移），请重点审批；
- ②③④ 是收尾性改动；
- ⑤ 是执行项。批准后按 ①→②③④→⑤ 顺序施工，分支 + PR 评审后合并（遵 CONTRIBUTING 分级规范）。
- ⑥ 随本轮一并施工（精校台 + 裁决升级）；其 P1/P2 借鉴项（分类细化/体例句/独立句读版权闸/契约测试）另批。
