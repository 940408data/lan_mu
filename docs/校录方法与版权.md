# 校录方法与版权

本文档说明兰木（lan_mu）项目古籍校录的**双源定位**（CHM 底本 + 识典 OCR 对校本）、**校对与精校全流程**（含真实举例），以及**校录成果的公开传播与版权风险**。与 `docs/识典古籍对校方法.md`（识典专项细节）互补，后者为本文档第 4 节的深入参考。

> ⚠️ 版权部分为技术整理与一般性建议，不构成法律意见。实际公开部署前请核实底本来源许可并咨询法律顾问。

## 一、引言：双源校录理念

项目核心理念「一次校录，多态呈现」——同一份结构化 YAML（`works/<id>/text.yaml`）由版面引擎产出 Web/PDF。**校录质量决定产物质量**。校录采用**双源互证**：

- **底本**（CHM 电子本）：经注全文的权威来源。
- **对校本**（识典 OCR 粗校）：发现底本错误的次要参照。

两者分工：底本给"应当是什么"，对校本查"底本哪里错了"。差异时**以底本为准**——除非对校本揭示底本的明确错误（PUA 缺字、经文误排）。

## 二、双源定位与作用

### 2.1 CHM 电子本（权威底本）

- **是什么**：本地《四书章句集注》CHM 电子本（`input_data/四书章句集注.CHM` → 抽取为 `input_data/chm_extract/*.htm`）。
- **特点**：
  - **结构化**——经文为纯文本大字，朱熹注文用 `<font color="#3366cc" size=-1>` 蓝色小字标记，章界由连续空段（`<br/><br/>`）分隔。
  - **经注俱全**——经文 + 朱熹集注全帙，简体（GB2312 编码）。
- **作用**：校录的**主底本**——经注全文来源、结构权威。校录即从此抽取。
- **缺陷**（须精校补）：
  1. **PUA 损字**——底本用 PUA 私有码点（`&#62451;` 等，`≥0xE000`）表示罕见字，抽取脚本 `clean()` 会**静默删除**导致缺字（详第 4.3 节）。
  2. **偶有经文误排入注**——底本把本属经文的片段排进 `<font>` 注，致 j 经文缺、z 注多（详第 4.4 节）。
  3. **底本读法偶异于通行本**——如「孝悌之養」（通行本作「義」）。此类为底本读法，非结构性误排，依「訛奪依 CHM 校」原则保留（详第 4.6 节）。
- **定位**：**权威**——差异时以 CHM 为准；「CHM 正确的不采信识典」。

### 2.2 识典古籍 OCR 粗校（次要对校本）

- **是什么**：[识典古籍](https://www.shidianguji.com)《四书章句集注》`version=32` 影印图片本 + 前端渲染的「粗校」文本层。
- **特点**：
  - **影印原页 OCR**——识典对扫描影印的原版古籍页做 OCR，产出简体经文文本层（在 DOM `document.body.innerText`）。
  - **仅经文、无注文**——粗校只 OCR 了经文大字，朱熹注文不在粗校层。
  - **反爬严**——字节跳动 `a_bogus`/`msToken` 签名，WebFetch 与 curl 直调 API 均被拒，须 Playwright stealth（`channel:'chrome'` + `navigator.webdriver=false`）让浏览器 JS 自签，截 DOM innerText（详 `docs/识典古籍对校方法.md`）。
- **作用**：**次要对校本**——价值在**发现 CHM 底本的明确错误**（PUA 缺字可对正字、经文误排可定位），而非逐字照搬。
- **缺陷**（不可盲信）：
  1. **注引文混入经文**——OCR 不辨大字/小字，把朱熹注引文混进经文（见第 4.5 节例）。
  2. **错字、重复段**——OCR 误识。
  3. **无注文**——注文对校需依 CHM 底本 + 朱熹体例。
- **定位**：**次要**——仅作 CHM 错误的发现器，不作底本。

### 2.3 Wikisource（公版参考，可选第三源）

- `zh.wikisource.org` 的《四书章句集注》为公版整理文本，MediaWiki API 可抓、无反爬。
- **作用**：底本来源的公版核证/补缺——若 CHM 底本来源存疑（见第 6 节），可改从 Wikisource 重新校录；亦可用于注文对校的辅助参照。
- 现有作品 `meta.yaml` 的 `sources` 已引用（如 `daxue` 源自 `zh.wikisource.org/zh-hant/大學章句`）。

## 三、校对流程（初校 / 粗校）

从 CHM 抽取到结构化 YAML，产出校录草稿。

### 3.1 抽取（tools/extract-*.js）

抽取脚本（`extract-lunyu.js` / `extract-mengzi.js`，结构同）：

1. **GBK 解码**——`new TextDecoder('gbk')`（或 gb18030）解 CHM 字节流。
2. **取 `content_uniq`**——正文区 `<DIV class="content_uniq">`。
3. **font 占位提注**——`<font[^>]*>…</font>` 替换为占位符，解跨 `<br/>` 的长注。
4. **`<br/>` 切段**——章界（连续 ≥2 空段 flush）分组，章内经注碎片合并：每章 = 1 j（经文）+ 1 z（注，○ 连碎片）。
5. **转换**——引号 `""''` → `「」『』`；opencc `s2tw` 简→繁；CORRECT 表修过度转（`嘆→歎`、`遊→游`、`慾→欲`、`系→繫`、`吊→弔`、`慼→戚`、`裡→里`、`並→并`、`範→范`）。
6. **○ 启发式**——rule A（注音段末、其后跟释义则补 ○）；rule B（各家引论 `程子曰`/`趙氏曰`… 前补 ○，首位并入释义者人工复核）。

**产出**：`text.yaml` 草稿（`sections[].blocks[]`，`{type: j|z, text}`）。

```bash
# 论语卷抽取（首篇加 --header --vol）
node tools/extract-lunyu.js input_data/chm_extract/21.htm --name=衛靈公第十五 --header --vol=八
# 孟子卷抽取
node tools/extract-mengzi.js input_data/chm_extract/30.htm --name=公孫丑章句上 --header --vol=三
```

> 中庸/序说等用单空段分章，默认 ≥2 空段阈值会误并，须用 loose 阈值（≥1 空段）重抽——见 `tools/extract-lunyu.js` 改阈值副本或临时脚本。

### 3.2 结构核验

正文 j 块数 = j 总数 − 抬头块（卷名 + 作者 + 篇名），须合篇旨「凡 N 章」：

| 作品 | 篇旨 | 正文 j 块 |
|---|---|---|
| lunyu8 | 衛靈公第十五 凡四十一章 + 季氏第十六 凡十四章 | 41 + 14 |
| mengzi3 | 公孫丑章句上 凡九章 | 9 |
| mengzi4 | 公孫丑章句下 凡十四章 | 14 |

不符则回查抽取（如 mengzi3 第二章「夫子加齊之卿相…曰惡是何言也」朱子本为一章，extract 误拆为 3 j + 2 z，须合并回 1 j + 1 z）。

### 3.3 字符扫描（opencc 残留）

CORRECT 表已自动处理 9 字，但须扫**表外残留**，按 CHM 原文修：

| 误（opencc 过度转） | 正 | 例 |
|---|---|---|
| 雲 | 云（云=说） | 「書雲」「史記雲」→「書云」「史記云」（云=说，非雲雨） |
| 粗 | 麤 | 「粗衰」→「麤衰」（朱熹用麤） |
| 髮 | 發 | 「天理髮見」→「天理發見」（發=显现，非髮） |
| 逾 | 踰 | 「逾牆」→「踰牆」 |
| 願 | 愿 | 「鄉人之願者」→「愿者」（愿=谨愿） |

**项目约定保留**（不作"修正"，与已入库卷一致）：

| CHM/通行 | 项目用 | 说明 |
|---|---|---|
| 並 | 并 | CORRECT 表 `並→并` |
| 徧 | 遍 | 通行本徧，项目用遍 |
| 箇 | 個 | 通行本箇，项目用個 |

> 判断原则：opencc 两边都转的（如 `征→徵`）不构成比对差异；只查**底本真缺/真异**。

## 四、精校流程（识典对校）

初校草稿完成后，用识典 OCR 粗校对校，发现并修正 CHM 底本错误。

### 4.1 取识典 OCR 经文（Playwright stealth）

识典反爬严，须 stealth 浏览器让 JS 自签 API，截 DOM innerText（粗校文本层）：

```javascript
const { chromium } = require('playwright');
const b = await chromium.launch({
  channel: 'chrome',                          // 用系统 Chrome（自带 chromium 版本可能不匹配）
  headless: true,
  args: ['--no-sandbox', '--disable-blink-features=AutomationControlled']
});
const ctx = await b.newContext({ userAgent: 'Mozilla/5.0 (X11; Linux x86_64) ... Chrome/146.0.0.0 ...' });
const p = await ctx.newPage();
await p.addInitScript(() => Object.defineProperty(navigator, 'webdriver', { get: () => false }));
await p.goto('https://www.shidianguji.com/book/HY0004/chapter/<chapterId>?version=32',
  { waitUntil: 'networkidle', timeout: 60000 });
const txt = await p.evaluate(() => document.body.innerText);   // 粗校经文（含导航/页脚，须截取）
```

章节 ID 从 book 页 SSR 的 `chapterGroups` 用 Python `re.findall` 提取（**勿用 `grep -oE`**，minified 单行跨式匹配会回溯爆炸）。孟子章节 ID 见 `docs/识典古籍对校方法.md`。

### 4.2 逐章对齐

识典经文按 `○` 分章，与 `text.yaml` 的 j 块逐章对齐：

1. **剥引号**——识典用 `" " ' '`，本项目用 `「」『』`；先统一再比，否则引号差异淹没真差异。
2. **多重集 diff**——找每章「本多/本少」字符（不定位，快速筛查）。
3. **逐字贪心对齐**——定位差异段，重点看**非引号字符**的缺/异。

```javascript
// 剥引号后逐字对齐，找首差
function stripQ(s){return s.replace(/["“”‘’「」『』]/g,'');}
// 识典章 = innerText.slice(章名, 'Next').split('○')
// 我方章 = text.yaml j 块（去前 3 抬头）
// 逐字比，记录首差位置 + 上下文
```

### 4.3 PUA 损字扫描与回填（关键陷阱）

**什么是 PUA 损字**：CHM 底本用 Unicode 私有使用区（PUA，U+E000–U+F8FF）码点表示罕见/异体字（私有字形映射）。抽取脚本 `clean()` 为防乱码，对 `&#NNNNN;` 实体判断 `code ≥ 0xE000 ? '' : 还原`——**PUA 实体被删空**，致经文/注缺字（如「吾&#62451;」→「吾」，缺"惛"）。

**扫描**（须用 node，`grep` 在 GBK 字节流上会漏）：

```javascript
const h = new TextDecoder('gb18030').decode(fs.readFileSync('NN.htm'));
const re = /&#(\d+);/g; let m;
while ((m = re.exec(h))) {
  if (+m[1] >= 0xe000) {
    console.log(m[0] + '(U+' + (+m[1]).toString(16).toUpperCase() + '): …'
      + h.slice(Math.max(0, m.index-60), m.index+60).replace(/<[^>]+>/g,'').replace(/\s/g,'') + '…');
  }
}
```

**回填三源**（正字无标准映射，须上下文推断）：

| PUA 实体 | 码点 | 正字 | 回填依据 |
|---|---|---|---|
| `&#62451;` | U+F3F3 | **惛** | ① CHM 自注「&#62451;，与昏同」② 识典经文「吾惛」 |
| `&#60073;` | U+EAA9 | **及** | 朱熹注体例「推己之心以及民」（固定表述） |
| `&#59960;`（字面 U+E3E1） | U+E3E1 | **蹙** | 反切「子六反」+ 上下文「曾西蹙然曰」 |
| `&#57881;`（U+E319，论语卷九） | U+E319 | **陗** | 识典/对校本「稜角陗厲」 |
| ● U+25CF 占位（论语卷九） | | **函** | 上下文「函，音含／不如函人之仁」 |

**本项目实历**：孟子卷一 2× `&#62451;`=惛（经文「吾惛」+ 注「惛与昏同」）、卷二 1× `&#60073;`=及（注「以及民」）、卷三 3× U+E3E1=蹙、3× ●=函；论语卷九 陗/涖/鼗×3 等。均经扫描定位、按三源回填，**最终 text.yaml PUA = 0**。

### 4.4 经文误排入注：判定与补回

**现象**：CHM 偶把本属经文（孟子/论语原文）的片段排进 `<font>` 注，致 j 经文缺该段、z 注多该段。

**判定关键**：看朱熹注是否在**注解**该片段——若注在解释该引文/该句，则该片段是经文（注的注释对象），CHM 误排。

**例 1（孟子卷一第四章「以刃與政」）**：
- CHM 把孟子第二次问「以刃與政，有以異乎」排入注。
- 判定：朱熹注「孟子又問而王答也」——注在解释"孟子第二次问"，证明该问是经文。
- 补回：从 z 注移回 j 经文。

**例 2（孟子卷二第三章「書曰：天降下民…」）**：
- CHM 把整段武王经文「書曰：『天降下民，作之君，作之師。惟曰其助上帝，寵之四方。有罪無罪，惟我在，天下曷敢有越厥志？』一人衡行於天下，武王恥之。此武王之勇也。而武王亦一怒而安天下之民。」排入注。
- 我方 j 经文仅有「文王一怒而安天下之民。今王亦一怒而安天下之民」，缺武王段（标准孟子此章有文王詩 + 武王書两段）。
- **判定依据**：z 注块朱熹注「**然所引與今書文小異，今且依此解之**」——朱熹在注解「書曰：天降下民」这段書引，证明该引文是经文（注的注释对象），非注文。CHM 误排，同例 1。
- 补回：武王经文从 z 注块移回 j 经文块（「文王一怒…」→「書曰天降下民…武王亦一怒…」→「今王亦一怒…」）。经字 2704→2770（+66）、注字 5013→4947（−66），总字数不变。

### 4.5 OCR 局限判断（不盲信识典）

识典粗校是简体 OCR，质量不如 CHM 电子本，常见问题：

**注引文混入经文**：孟子卷二第一章，识典经文出现「管籥之音，舉欣欣然」——实为朱熹注引文（讲钟鼓之乐），CHM 经文为「舉疾首蹙頞」（正确，讲疾首蹙额）。此为识典 OCR 把注小字混进经文大字。

**判断原则**：CHM 是电子本（结构化），识典是 OCR（粗）。差异时**查 CHM 原文确认**，CHM 正确的不采信识典。识典对校的价值在**发现 CHM 的明确错误**（PUA 缺字、经文误排），而非逐字照搬。

### 4.6 底本读法保留

CHM 底本读法偶异于通行本/识典：

| 处 | CHM 底本 | 识典/通行 | 处理 |
|---|---|---|---|
| 孟子卷一第三章 | 「孝悌之**養**」 | 「孝悌之**義**」 | 保留底本養（非结构性误排，依「訛奪依 CHM 校」） |
| 孟子卷一第六章 | 经文有「**王問也。**」 | 通行本无 | 保留底本（CHM 经文有之，识典 OCR 漏） |

此类为**底本读法**（非 PUA、非误排），属底本自身的读法选择/异文，**保留不改**——区别于第 4.3/4.4 的结构性错误（须修）。

## 五、校验与构建

### 5.1 校验（meta.expect 基准）

精校后字数/行数/葉数变化，更新 `meta.expect` 基准，`npm run validate` 自洽通过：

```yaml
expect:
  chars: 7717        # jChars + zChars（仅 CJK，不含标点）
  jChars: 2770       # 经字
  zChars: 4947       # 注字
  columns: 291       # 行
  halves: 37         # 半葉
  leaves: 19         # 葉
```

- `validate`：全作品数据基准校验（实得 ≠ 基准报错）。
- `verify`：幽兰复刻保真验收（dist 与根目录 `Youlan-Scroll.html` 逐字符比对，改引擎必跑）。
- pre-commit hook（`.githooks/`，`npm install` 经 `prepare` 自动配）：提交前自动 `validate`；改 `src/core|render|fonts|viewer/`、`works/youlan/`、`css/` 加跑幽兰 `verify`。

### 5.2 构建

```bash
npm run build -- --work=<id> --only=html   # 快速验证（宋版 html 不走 Playwright）
npm run build -- --work=<id>               # 全量（宋版三体 PDF；手卷含 JPG 长图）
```

宋版善刻不出长图，改用每字面一版 PDF（`--only=jpg` 对宋版空操作）。

## 六、校录成果的公开传播与版权

### 6.1 公版部分（可自由传播）

- **朱熹《四书章句集注》原文**（经文 + 朱熹注文文字）：朱熹（1130–1200），古籍，著作权保护期早已届满——**公版**。经注原文可自由使用、传播、演绎。
- **本项目校录整理**（`text.yaml` 的结构化、PUA 回填、误排修正、字符校正）：为整理工作，项目方可选择开源许可（如 CC-BY 4.0）公开传播。

### 6.2 需核证的底本链条

- **CHM 电子本**：来源待核证。若系某出版社/整理者的**整理本**（含独创性校勘成果），整理者享有整理作品权利，须获授权方可作底本；若系公版扫描/电子化（如 Wikisource），可自由使用。**建议：公开传播前确认 CHM 来源许可；存疑则改从 Wikisource 公版源重新校录**（现有 `meta.sources` 已引 Wikisource）。
- **识典 OCR 粗校**：仅作**内部对校参考**，**不发布识典 OCR 文本**。本项目 `text.yaml` 系 CHM 校录成果（经 PUA 回填/误排修正），**非识典 OCR 复制**，不构成发布识典文本。须遵守识典使用条款（反爬已用 stealth 绕过，对校属合理使用范畴；但勿批量抓取/再发布识典影印图或 OCR 全文）。

### 6.3 字体授权（高风险，严防外泄）

项目三级字体授权管线（`src/fonts/`，`fonts.yaml` 登记册）：

| 级 | 授权 | 用法 | 公开风险 |
|---|---|---|---|
| A | 开源（OFL 等，`lxgw-wenkai-tc`） | 子集 woff2 嵌入 dist | 无（可公开） |
| B | 免费商用但禁嵌入（`zhuque-fangsong`、`ac-gyosyo` 英椎行书） | 仅本机出图（`fontLocal` 双轨注入）；**不进 dist** | **高（若外泄）** |
| C | 付费 | 预留 | — |

**关键设计**：B 级字体在访客端只放 bare family name，本机预览由 `tools/serve.js` 经 `/b-fonts/` 路由注入（`file://` 字体在 `http://` origin 被 Chromium 阻止）；dist 不含此注入，B 级不外泄。`local()` 不命中会阻塞后续 `url()` 字体，故双轨。

**部署前必查**：dist 内无 B 级字体二进制（仅 A 级 woff2）。B 级泄漏到公开 dist = 侵权。

### 6.4 风险矩阵

| 项 | 风险 | 建议处理 |
|---|---|---|
| 朱熹经注原文 | 无（公版） | 可自由传播 |
| 本项目校录整理（text.yaml） | 低 | 选开源许可公开 |

| 识典影印图 | 无 | 本项目不收录影印图（自绘宋版版式），无此风险 |

### 6.5 公开传播合规清单

1. **核证底本**：确认 CHM 来源许可，或改从 Wikisource 公版源重新校录；`meta.sources` 如实标注底本与对校本来源。
2. **字体不外泄**：dist 仅含 A 级字体子集（woff2）；B 级字体二进制不得入 dist/仓库（`.gitignore` 已忽略 `src/fonts/src/`）。
3. **不发布第三方文本**：`text.yaml`/dist 为本项目校录成果，不含识典 OCR 文本或影印图。
4. **许可声明**：`aboutHtml` 标注公版声明 + 底本来源 + 整理许可（如 CC-BY）。
5. **对校脚本不入库**：识典抓取/对校脚本（`tools/_*.js`）以 `_` 开头被 `.gitignore` 忽略，本地使用，避免污染主分支与暴露抓取实现。
