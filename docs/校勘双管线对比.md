# 兰木校勘双管线对比：旧 M/P 管线 vs 网格基 G 管线

> 状态：2026-08-17。dev 分支当前**两条校勘管线并存**——旧 M/P 管线（句段级，`run.js` 主入口）与新 G 管线（网格基，`grid-*` 工具链）。新管线不删旧（保留对照，验收后下线）。两者共享校勘学内核（异文归类、四校书官、法理双本隔离）。
>
> 相关：[网格基流程重构方案](网格基流程重构方案.md)（G 管线设计）、[双书实施验收与量化评价](网格基重构-双书实施验收与量化评价.md)（§3 新旧量化对比）、[古籍校勘流水线](古籍校勘流水线.md)（旧 M/P 详）、[collation/README](../collation/README.md)

## 1. 旧 M/P 管线（句段级，现行）

九阶段，`collation/run.js` 主入口：

```
P0 装载 → P1 OCR → P1.5 清洗 → P2 AI初校 → P2.5 视觉复核 → P3 对齐 → P4 对校 → P4.5 簇核验 → P5 校书官 → P5b 全篇审查 → P6 双本出具 → P7 人工
 io.js    llm.js   cleanup.js   llm.js     reconfirm.js   align.js  diff.js   cluster.js   officer.js  full-review.js  export.js   flags
```

- **入口**：`node collation/run.js <书> [--step=align|diff|verify|officer|export|apply]`
- **入库**：`node collation/tools/build-works.js <书> <newId> [--from=transcribe]`（路线 A `grid.json` / 路线 B `grid-transcribe`）
- **对齐粒度**：句段级（`align.js` 句锚点 + 编辑距离兜底）
- **位置定位**：`segId` + `regionId`（需二次回查文件定位书影）
- **数据源**：多层——`shanben-v2.json`（旧OCR+整页重OCR仲裁）/ `aligned` / `diffs` / `clusters` / `verdicts`
- **改字**：`verdicts` resolved/suspended，P6 出具**一律不改字**（异文只入校勘记）
- **产物**：善本点校本.md / 现代本.md / 校勘记.md / 精校台.html / flags.yaml（公开 `data/` + 私有 `input_data/_derived/`）

## 2. 新 G 管线（网格基）

五阶段，`collation/tools/grid-*.js` 工具链：

```
G1 视觉逐格(基础层) → G2 参校对齐(overlay.variants) → G3 标签层(overlay.labels/sections) → G4 异文裁决 → G5 单一出口
 grid-transcribe.js      grid-overlay.js                grid-overlay.js              grid-officer/review/review-merge.js   grid-export.js
```

- **入口**：各 `grid-*.js` 独立调用（无单一 run.js；见各工具头部用法）
- **基础层**：`grid-transcribe.json` 逐格 `{col,row,char,start}`，唯一真相骨架
- **overlay 旁挂**：`grid-overlay.json` = `variants`（参校差异 oldOcr/modern）+ `labels`（j/z/title）+ `sections`（格坐标边界）+ `fixes`（裁决改字）
- **对齐粒度**：格级（`page/col/row` 直达书影）
- **改字通道**：`overlay.fixes`（`grid-review-merge.js` 唯一写入；`kind:sub` 改字 / `kind:insert` 补夺文；基础层指纹锁，幂等）
- **出口**：`grid-export.js` 从「基础层 + overlay + fixes」单源派生 `works/<id>/text.yaml`（songke）；善本点校本.md / 校勘记.md 二期

### G 管线工具速查

| 阶段 | 工具 | 职责 |
|---|---|---|
| G1 | `grid-transcribe.js` | 视觉逐格转写基础层 |
| G2+G3 | `grid-overlay.js` | 参校对齐 + 标签层（labels/sections）→ `grid-overlay.json` |
| G4 | `grid-officer.js` | 四校书官审议格级异文（复用 `officer.js`）→ `grid-officer.json` |
| G4 | `grid-review.js` | 精校台 HTML（格坐标 + 四官内嵌 + 人决） |
| G4 | `grid-review-merge.js` | 裁决 JSON → `overlay.fixes`（唯一改字通道） |
| G5 | `grid-export.js` | 基础层+overlay+fixes → `works/<id>/text.yaml` |

## 3. 对比

| 维度 | 旧 M/P | 新 G |
|---|---|---|
| 对齐粒度 | 句段级 | 格级 |
| 数据源 | 多层（shanben-v2/aligned/verdicts） | 单源（grid-transcribe + overlay） |
| 位置定位 | segId+regionId（二次回查） | page/col/row（直达书影） |
| 真异文噪声 | 句段错位伪异文（中庸≈13%、大学≈7%） | 锚分段，重叠区显式清单（→0） |
| 视觉读字 | 3 趟（整页重OCR + 列级 + 逐格） | 1 趟（逐格） |
| 经注判定 | judge-grid 列级 + 文本 match | overlay.labels（start 顶格→j / 退格→z，含 title 覆盖） |
| 章节切分 | 文本 match 正则（右經一章/右傳之X章） | overlay.sections 格坐标 |
| 改字通道 | verdicts resolved（P6 不改字） | overlay.fixes（唯一改字通道，裁决回写） |
| 入库完整度 | 大学 1 节 / 5923 字（缺序 12%） | 12 节 / 6745 字（含序） |
| 章节结构准确率 | 大学未生效（1 节） | 大学 12/12、中庸 34/34 |
| 人工精校 | flags.yaml 手工 + 精校台.html | 精校台-网格.html（格坐标 + 四官内嵌）→ decisions → fixes |
| 阶段数 | 9（P0–P7 + M6） | 5（G1–G5） |
| 出口 | export.js（verdicts → 善本点校本） | grid-export.js（overlay → text.yaml）；公开本/校勘记二期 |

## 4. 共享内核与通用性待办

新管线复用旧校勘学模块（省时省费，不重写）：

- **四校书官**：`grid-officer.js` 复用 `officer.js` 的 `officerOpinion` / `aggregate`（证据分级加权 + 底本优先 β + 悬置三规则）
- **参校差异**：`overlay.variants`（oldOcr / modern 的 sub / extra / missing）替代旧 P3 句段对齐 + P4 diff
- **视觉复核**：`verifyChar` 整页图核字可挂 G4
- **法理双本隔离**：善本点校本（当涂郡本，公开 A 级）+ 现代本（儒藏本，私有 B 级，不入 dist）沿用

### 通用性验证（待办）

> 上述复用**仅在大学 / 中庸的格级异文上验证**（大学 38 条真实 qwen、中庸 mock 102 条），**未在其他书上完整跑 G1→G5 全流程**。「省时省费」以双书为证，但通用性未证——换其他书（异文类型分布、版面、经注体例不同）可能暴露覆盖与适用性问题。列待办：

- **异文归类**：旧 P4 diff 的完整归类（异体 / 真异文 / ocr疑 / 夺 / 衍）在新管线**未显式接入**——`overlay.variants` 只记 sub / extra / missing 差异，归类靠 `grid-officer` 审议时隐式。换其他书（异文类型分布不同）覆盖是否够，未证。
- **四校书官适用性**：朱熹章句体例（解题注 → 经 → 详注）外的书（如论语 / 孟子集注大部头、非朱熹体例），四官方法论倾向是否仍贴切，未证。
- **VARIANT_MAP 异体归一表**：扩至论语 445 页 / 孟子 547 页大部头需扩充，对齐失配的 fuzzy 兜底在大量数据上未压测。
- **G5 出口边界**：`cellsInRange` 跨页切片、`deriveBlocks` 的 title / ○ 处理仅在双书验过，其他书版面（重叠区 / 缺页 / 章题格式）未压测。

**待办**：选 1–2 部其他书完整跑 G1→G5（逐格补齐 → overlay → 四官 → 精校台 → fixes → text.yaml → songke 渲染），验证异文归类 + 四校书官 + 出口在新管线的通用性，确认省时省费不以牺牲覆盖为代价。

## 5. 关系与迁移

- **新不删旧**：旧 `run.js` / `build-works.js` / `export.js` 保留可跑，作对照验收基线
- **S5 下线计划**（[方案 §4.3](网格基流程重构方案.md)）：G5 出口对照通过后，旧 `build-works.js` 下线，路线 A/B 消失，`recollate` / `judge-grid` 废弃
- **迁移期**：旧管线仍可跑新作品（`run.js` mock 兜底）；新作品可直接走 G 管线
- **当前**：G1–G5 已实施，大学/中庸双书验收（见[验收评价](网格基重构-双书实施验收与量化评价.md)）；二期 meta / 善本点校本 / 校勘记 / 抽共享 `songke-pipeline.js` / fixes 填入后重跑
