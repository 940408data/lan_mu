# 点校系统功能方案

## 一、背景与目标

### 1.1 现状
兰木（lan_mu）项目目前分两部分：**构建**（`tools/cli.js build`，YAML→HTML/PDF）与**前端服务**（`tools/serve.js`，托管 dist）。校录目前是手工流程：以 CHM 电子本为底本、识典 OCR 为对校本，经 `extract-*.js` 抽取 + 人工精校产出 `works/<id>/text.yaml`（见 `docs/校录方法与版权.md`）。

### 1.2 目标
将「校录」从「构建」中**独立成「点校系统」**——先点校、后构建，二者解耦迭代。点校系统**个人使用**，核心思路：**以古代善本扫描件为底本（公版、可公开传播），以现代点校本扫描件为参考校正**，经 OCR → AI 初校 → 人工精校，产出可入构建系统的 `text.yaml`。

### 1.3 与现有手工流程的关系
现有 CHM 流程是点校系统的「结构化底本」特例（CHM 已含经/注 HTML 标记，`extract-*.js` 规则抽取）。点校系统将其**泛化**到原始善本扫描（无结构图 → OCR → AI 结构化），AI 初校承担 `extract-*.js` 在扫描场景的角色。CHM 流程仍可作为「已有电子本」的快通道并存。

## 二、核心思路

```
善本扫描件（底本，公版）         现代点校本扫描件（参考，版权·仅本地）
        │                                  │
       OCR                                OCR
        │                                  │
   AI 初校（结构化 text.yaml 草稿 + 疑难点标注）
        │
   人工精校（标准1: 善本扫描原貌 ｜ 标准2: 点校本异文）
        │
   works/<id>/{text,meta,…}.yaml（校录成果）→ 构建系统
```

- **底本**：古代善本扫描件（公版，可公开传播、可入库）。
- **参考**：现代点校本扫描件（版权，仅本地对校、不入库不公开）。
- **流程**：善本 OCR → AI 初校 → 人工精校。

## 三、原材料管理

### 3.1 两类原材料

| 类 | 善本（底本） | 点校本（参考） | 说明 |
|---|---|---|---|
| **A 类**（原始扫描） | 扫描件 [pdf/jpg] | 扫描件 [pdf/jpg] | 需完整 OCR 管路 |
| **B 类**（扫描+OCR） | 扫描件 + OCR 结果 | 扫描件 + OCR 结果 | 跳过 OCR，直接用提供的文本 |

系统同时支持 A/B：若原材料已附 OCR 结果（B），跳过 OCR 步骤、直接进 AI 初校；否则（A）走完整 OCR 管路。

### 3.2 存储布局

```
input_data/pointcheck/<work-id>/
  shanben/                  # 善本（底本，公版）
    pages/{001.jpg..}       # 扫描页图
    ocr/{001.txt..}         # OCR 结果（A 类由本系统产出，B 类随原材料提供）
    source.yaml            # 善本出处（馆藏/版本/公版声明）
  dianjiao/                # 现代点校本（参考，版权·本地不入仓）
    pages/{001.jpg..}
    ocr/{001.txt..}
    source.yaml            # 点校本出处（出版社/版次，仅本地）
  work.yaml                # 点校元数据：章数、卷次、底本/参考来源、OCR 引擎、状态
```

- **善本扫描（公版）**：可入仓（或 git-lfs），可公开传播。
- **点校本扫描（版权）**：`.gitignore` 忽略，仅本地对校，不公开、不发布其 OCR 文本。
- **产出** `works/<id>/{text,meta,seals,ornaments}.yaml`：校录成果，入构建系统。

### 3.3 底本选择（公开善本）
- 四书：宋刻本《四书章句集注》公版善本扫描（如国家图书馆/哈佛燕京/内阁文库开放扫描，宋刻远超版权期）。
- 现代点校本参考：如《儒藏》本、《朱熹集》现代点校（中华书局等），版权——仅作对校参照。

## 四、OCR 管路

### 4.1 流程
`pdf/jpg` → 页图提取（pdf-lib 或 `pdftoppm`）→ OCR 引擎 → `text + 页/位置映射`（供精校对照定位）。

### 4.2 引擎选型

| 引擎 | 许可 | 中文/竖排 | 适用 | 取舍 |
|---|---|---|---|---|
| **PaddleOCR** | Apache 2.0 | 强，支持版面+竖排 | 善本竖排、点校本横排 | 主力（开源、本地、免费） |
| Tesseract | Apache 2.0 | 一般（chi_tra/sim + OSD） | 点校本横排 | 备选 |
| LLM vision（Claude/GPT-4V） | API | 极强（异体字/竖排/残字） | 善本疑难页/低置信字 | 辅助（成本，仅难点） |

- **善本**（竖排右起、无标点、异体字多、扫描质量不一）：PaddleOCR 版面分析（竖排）为主，**低置信度页/字转 LLM vision** 复核。
- **点校本**（横排、有标点、简/繁）：PaddleOCR/Tesseract 标准 OCR。
- OCR 产出保留**页码与位置 bbox**，供精校时图文对照定位。

### 4.3 善本 OCR 难点与对策
- **竖排右起**：PaddleOCR 版面模型识别列序；或预旋转/切列。
- **异体字/避讳字**：OCR 易误识 → LLM vision 辅助 + 人工精校对照善本原图。
- **残字/污损**：OCR 低置信 → 标记，人工对照善本扫描定字。
- **经注大小字**：OCR 仅出文本时不分大小字；需用 bbox 高度/字号区分大字（经）与小字（注），传给 AI 初校。

## 五、AI 初校

### 5.1 定位
AI 初校 = 把善本 OCR 的**非结构化文本**结构化为 `text.yaml` 草稿，并标注疑难点供人工复核。承担 `extract-*.js` 在扫描场景（无 HTML 结构）的角色。

### 5.2 输入
- 善本 OCR 文本（+ bbox 字号信息，区分大字经/小字注）。
- 点校本 OCR 文本（参考，可选）。
- 上下文：卷次、篇名、凡 N 章（可从点校本或先验给出）。

### 5.3 LLM 任务
用 Claude（结构化能力强）执行：
1. **经/注分离**：按 OCR 字号（大字=经 j，小字=注 z）或内容（经=原文、注=释义/注音/引论）切 j/z 块。
2. **章界**：识别章界（凡 N 章、双空段、章首重复等），每章 1 j + 1 z。
3. **繁体归一**：opencc `s2tw` + CORRECT 表（复用现有 `extract-*.js` 的修正映射：嘆→歎、遊→游 等）。
4. **○ 规则**：rule A（注音→释义补 ○）、rule B（引论前补 ○，含赵氏曰/程子曰等注家）。
5. **疑难点标注**：低置信字、残字、经注难辨处 → flag 列表（页码+位置+候选）。
6. 引号 `""''`→`「」『』`；校记〔N〕注脚识别（暂标，人工决断删/留）。

### 5.4 输出
- `text.yaml` 草稿（`sections[].blocks[]`，`{type:j|z,text}`）。
- `flags.yaml`：疑难点（页/位置/OCR候选/LLM候选/置信度），供人工精校聚焦。
- `meta.yaml` 模板（seed/expect 待填）。

## 六、人工精校

### 6.1 双标准

| 标准 | 来源 | 作用 |
|---|---|---|
| **标准 1：原始善本扫描件** | 底本原貌（公版权威） | 逐字核对 OCR/LLM 是否读对、异体字原貌、残字定字、底本读法 |
| **标准 2：现代点校本** | 现代整理（参考） | 异文/缺字/句读/分章参考；揭示底本可能的误排/夺文 |

原则：**底本（善本扫描）为准**，点校本作参考——点校本与底本异时，查善本原图确认；底本明确错误（残字 OCR 缺、误排）方依点校本/体例修正。同 `docs/校录方法与版权.md` 第四节。

### 6.2 精校工具（对照视图）
一个本地 web 对照页（扩展 `tools/serve.js` 或独立），三栏 + 页导航：

```
┌─────────────┬─────────────────┬─────────────┐
│ 善本扫描图   │  text.yaml 编辑 │ 点校本（OCR）│
│ （底本原貌） │  （逐字对照改）  │ （参考）     │
│  OCR overlay │  flags 高亮难点 │              │
└─────────────┴─────────────────┴─────────────┘
        逐页 / 逐章导航        PUA/缺字/异文标注
```

- 左栏：善本页图 + OCR 文本 overlay（可点字定位）。
- 中栏：`text.yaml` 当前块，可编辑；`flags.yaml` 疑难点高亮。
- 右栏：对应点校本页/章 OCR，作异文参考。
- 操作：逐字校改、PUA 回填（三源：善本原图/点校本/朱熹体例）、误排补回、章界调整、底本读法保留/标注。

### 6.3 精校关注点（同现有精校经验）
- **PUA/残字**：善本扫描看原字定字（无 PUA 码点问题，扫描直接识字——优于 CHM PUA 损字）。
- **异体字规范**：按项目惯例归一（并/遍/個 等）。
- **经文误排入注**：点校本可揭示底本误排（如孟子卷二第三章武王经文误入注），依朱熹注体例判定补回。
- **底本读法**：底本异文（如 養 vs 義）依「訛奪依底本校」保留，标注。
- **章界/章数**：核 j 块 − 抬头 = 凡 N 章。

### 6.4 输出
- 最终 `works/<id>/{text,meta,seals,ornaments}.yaml`。
- `meta.expect` 基准（chars/jChars/zChars/columns/halves/leaves，`npm run validate` 自洽）。

## 七、与构建系统衔接

```
点校系统                        构建系统（lan_mu 现有）
─────────                      ──────────────────
善本+点校本                      works/<id>/*.yaml
  ↓ OCR/AI/精校                      ↓
works/<id>/*.yaml  ──────→   tools/cli.js build → dist
（校录成果）                    （HTML/PDF/前端服务）
```

- **接口**：点校系统产出标准 `works/<id>/{text,meta,seals,ornaments}.yaml`，构建系统直接消费（`layout: songke` 等不变）。
- **解耦**：点校系统可独立迭代（OCR 引擎、LLM、精校 UI）；构建系统独立（版面/字体/渲染）。校录质量提升不扰动构建，反之亦然。
- **校验**：点校系统产出后跑 `npm run validate`（expect 基准）；改版面跑 `npm run build --only=html` 快验。

## 八、技术选型建议

| 组件 | 选型 | 理由 |
|---|---|---|
| OCR 主力 | PaddleOCR（Apache 2.0） | 开源、本地、免费、中文强、支持竖排版面 |
| OCR 辅助 | LLM vision（Claude） | 异体字/残字/低置信页，高质量（成本可控，仅难点） |
| AI 初校 | Claude（结构化） | 经/注分离、章界、○ 规则、疑难标注 |
| 精校 UI | 扩展 `tools/serve.js` 或独立本地 web | 三栏对照 + 页导航，复用现有服务框架 |
| 存储 | 文件系统（善本公版可 git-lfs；点校本本地 gitignore） | 个人使用，无需云/多用户 |
| 衔接 | `works/<id>/*.yaml` → `npm run build` | 复用现有构建管线 |

## 九、版权与公开传播

（与 `docs/校录方法与版权.md` 第六节一致，此处聚焦点校系统）

- **善本扫描件（底本）**：公版（古代善本远超版权期），可入库、可公开传播。
- **现代点校本扫描件/OCR（参考）**：版权，**仅本地对校**——不入仓（`.gitignore`）、不公开、不发布其文本。点校本仅作对校参照，校录成果不复制点校本版权内容。
- **校录成果（text.yaml）**：基于公版善本 + 整理工作，可选开源许可（如 CC-BY 4.0）公开。
- **OCR 引擎/LLM**：开源引擎（Apache 2.0）无版权风险；LLM API 属服务使用，输出为校录整理（非复制版权作品）。
- **风险点**：勿批量公开点校本扫描/OCR；勿将版权点校本内容复制入 `text.yaml`（`text.yaml` 应源自善本底本，点校本仅对校参照）。

## 十、实施路线（分阶段，个人迭代）

| 阶段 | 内容 | 产出 |
|---|---|---|
| **P1 原材料 + OCR** | 存储布局、善本/点校本扫描入库、PaddleOCR 管路（竖排/横排）、LLM 难点辅助 | `shanben/ocr/`、`dianjiao/ocr/`（带 bbox） |
| **P2 AI 初校** | Claude 结构化（经/注/章界/○/繁体）+ 疑难标注 | `text.yaml` 草稿 + `flags.yaml` |
| **P3 人工精校 UI** | 三栏对照视图 + 页导航 + flag 高亮 | 最终 `text.yaml` + `meta.expect` |
| **P4 构建衔接** | `works/<id>/*.yaml` → `npm run build`（HTML/PDF） | dist 产物 |

每阶段可独立验证、独立推进；P1 可先用一部小经（如《大学》）跑通全链路再扩四书。

## 十一、附录：与现有手工流程的差异

| 维度 | 现有手工（CHM） | 点校系统（善本扫描） |
|---|---|---|
| 底本 | CHM 电子本（结构化 HTML） | 善本扫描件（无结构图） |
| 经/注分离 | `extract-*.js` 按 `<font>` 标记 | OCR bbox 字号 + AI（LLM） |
| 对校本 | 识典 OCR 粗校 | 现代点校本扫描 OCR（更权威） |
| 结构化 | 脚本规则 | LLM 结构化（泛化） |
| 精校 | 逐章对齐脚本 + 人工 | 三栏对照 UI + 人工 |
| 底本公开性 | CHM 来源待证 | 善本公版，可公开传播 |

点校系统是现有手工流程的**系统化 + 泛化**：从依赖 CHM 结构 → 通用善本扫描；从规则抽取 → AI 结构化；从识典对校 → 现代点校本对校。校录成果仍为标准 `text.yaml`，无缝衔接构建系统。
