# 宋版影刻直出引擎方案：逐格数据直渲作品页

> 分支：`engine/songke-facsimile`（worktree `.claude/worktrees/songke-facsimile`）
> 日期：2026-08-18。状态：方案 + 实施（大学章句实例验证）。
> 上游：`collation/` G 管线（G1 逐格 → G2/G3 overlay → G4 裁决 → fixes）。

## 1. 动机：text.yaml 中间层的信息损失

现行链路是「逐格数据 → G5 压平为 text.yaml（j/z 连续文本）→ songke 引擎**重排** → 作品页」。压平与重排丢掉的信息：

1. **坐标全丢**：页/列/行坐标在 text.yaml 中不存在，重排后的列界是算法近似，非原刻真实列界。
2. **双行切分失真**：原刻注文双行的真实切点（哪两字同行并立）被压平，songke 按「双行均齐」算法重新猜切。
3. **空格消失**：原刻留白格（敬空、阙字、章末余白）在连续文本里无法表达。
4. **证据链断裂**：裁决 fixes 的 from/to/evidence 在 text.yaml 里只剩一个最终字，读者看不到「此字曾校」。
5. **页界丢失**：text.yaml 无页概念，重排后叶次与原刻叶次不再对应，书影对照困难。

而逐格数据（`grid-transcribe.json` + `grid-overlay.json`）天然是全真的原刻列阵：**35 页 × 16 列 × 15 行、逐字坐标、j/z/title 标签、空格占位、裁决证据链**。直接以其为渲染源，可得「影刻级」还原——这不是 songke 重排能逼近的。

## 2. 核心决策：新建 songke 子引擎，不改 songke 本体

| 维度 | songke（重排引擎） | songke-facsimile（影刻直出，本方案） |
|---|---|---|
| 数据源 | text.yaml 连续文本（无坐标） | grid.yaml 逐格坐标（全真列阵） |
| 排版 | typeset 算法重排切列 | 零重排，按原格渲染 |
| 注文双行 | 算法均齐猜切 | 原刻真实双行（相邻两转写列配对） |
| 三版变体 | 疏朗/雅正/宋槧 三版递转 | 无（原刻只有一种版式） |
| 叶次 | 重排后新叶次 | 与原刻叶次一一对应，可对书影 |
| 校勘层 | 无 | fixes 快照挂格，读者可交互查阅 |
| 适用 | 无逐格数据的通行本校录 | 有 G 管线逐格数据的善本还原 |

**若在 songke 上改**：数据模型不同（流式文本 vs 格阵）意味着 typeset 主流程（三版变体、卷界补列、均齐双行）大半成为岔路死代码，违背「依赖方向单向、引擎纯粹」的现有架构。

**新建子引擎的落点天然干净**：分派点是注册式的（`src/core/model/scroll.js` 的 `MODELS = { scroll, songke }`），新增 `songke-facsimile` 只需登记一项，`meta.layout` 切换，songke 本体零改动。这与论语适配的「登记式适配」先例一致。

## 3. 数据流

```
collation/data/<书>/grid-transcribe.json   （基础层，永不改）
collation/data/<书>/grid-overlay.json      （labels / sections / fixes）
        │
        ▼  collation/tools/grid-to-work.js <书> <新作品id>
works/<新作品id>/grid.yaml                  （应用 fixes 后的快照 + 证据链）
        │
        ▼  src/core/load.js（装载 grid.yaml）
src/core/model/songke-facsimile.js         （LayoutTree，kind: 'songke-facsimile'）
        │
        ▼  src/render/html-songke-facsimile.js（壳 + payload + 字体栈 + T2S）
src/viewer/songke-facsimile.js             （浏览器端逐格渲染）
```

### 3.1 grid.yaml（作品数据层新成员）

```yaml
work: 大学章句
base: { file: grid-transcribe.json, sha256: af85ff6a… }
exportedAt: 2026-08-18T…
layout: { cols: 16, rows: 15 }
pages:
  - n: 2
    cols:
      - { role: j, chars: "大學章句序　　　　　　" }   # 定长 rows 串，空位 U+3000
      - { role: z, chars: "…" }                        # 注文转写列（双行拆列之一）
sections: […]    # 从 overlay.sections 拷入（章节目录/导航）
fixes: […]       # 已应用的 sub（改字已入 chars）+ 未入版面的 insert，证据链快照
```

- **sub 类 fixes**：导出时应用（chars 已是裁决后字），同时保留 fix 条目供校勘交互层。
- **insert 类 fixes**：**默认不入版面**——影刻直出的版面语义是「原刻原貌」，夺文补入属于点校本范畴；若需补入正文成书，走 G5 text.yaml + songke 重排通道。insert 条目保留在 fixes 快照中，渲染时以栏外标记提示「参校本多出」。

### 3.2 渲染规则

- 每葉 = grid 一页：转写列 col1（最右）→ colN（最左），自右向左排。
- **j / title 列**：大字整列，格高均分版框。
- **z 列配对**：同一页内连续 z 列两两配对（右列=双行右行，左列=双行左行），合成一个物理列宽的双行小字；落单 z 列按单行小字渲染并警告。
- **空格**：U+3000 位留白占位（敬空/阙字/余白全真保留）。
- **版心**：叶中央鱼尾 + 书名 + 原刻叶次（页码即叶次，天然准确）。
- **朱点**：逐格数据无标点信息，首版为白文无点（句读朱笔若二期转写入格，可复用 songke 朱点样式）。

## 4. 与精校台的结合

精校台（`grid-review.js` 生成的 `精校台-网格.html`）与影刻直出共享同一个渲染对象——逐格矩阵——但服务两种角色：

| | 精校台 | 影刻作品页 |
|---|---|---|
| 读者 | 校勘者（私人） | 公众读者 |
| 疑问格 | 红框标注 + 裁决面板（改字操作） | 校勘标记 + 悬停证据（只读展示） |
| 书影 | 并列对照（辅助裁决） | 不嵌（作品页保持纯粹） |
| 输出 | 裁决 JSON → fixes | grid.yaml → 作品 |

结合点两层：

1. **渲染思想同源**：精校台已实证「竖排网格必须显式 grid-row/grid-column 定位、禁 grid-auto-flow」（空格无 DOM 占位时防挤位错列），影刻 viewer 直接沿用此坐标定位纪律；后续可把公共格阵渲染抽为 `src/viewer/grid-view.js`，精校台二期切用，消除双份实现。
2. **校勘层演化**：精校台的疑问格标注在作品页演化为**只读校勘交互层**——有 fix 的格子字下施小朱记，悬停/点击浮出证据链（格字 → 裁决字、旧OCR / 今本、裁决人注记、裁决时间）。这是「数字善本」相对纸本的独门价值：校勘成果不止于定本文字，而是可查验的证据网。

## 5. 实施步骤

- S1 `collation/tools/grid-to-work.js`：grid + overlay → grid.yaml（sub 应用、insert 快照、labels 内联、base 指纹校验）
- S2 `src/core/load.js`：装载 grid.yaml（有 grid.yaml 时 text.yaml 可缺）
- S3 `src/core/model/songke-facsimile.js`：LayoutTree 构建 + stats
- S4 `src/render/html-songke-facsimile.js` + `src/viewer/songke-facsimile.js`（渲染壳 + 逐格渲染）
- S5 分派登记：`MODELS['songke-facsimile']`；cli validate/build 按 kind 分派（首版仅 HTML；PDF 二期）
- S6 大学实例：`works/daxue-facsimile/`（grid-to-work 生成 + meta 参考 daxue-songben-g5 改 id/title/layout）
- S7 验证：`validate` 统计 + `build --only=html` + 浏览器实拍对比原刻书影与精校台渲染

## 6. 边界与二期

- 首版仅 HTML；PDF（每叶面一版）二期，复用 `pdf-songke.js` 的壳。
- 朱点句读、半叶/异形叶（specialPages）的版面特判二期。
- 精校台切换到共享 grid-view.js 二期（不动现有精校台，先立后破）。
- 中庸/论语（分卷）实例验证二期：分卷书 page 全局连续，直出天然支持（无需卷界补列——原刻卷界本来就在数据里）。
