# 识典古籍对校方法

[识典古籍](https://www.shidianguji.com) 收录《四书章句集注》等古籍，可作为本校录项目的对校本。但其 `version=32` 等为**影印图片本**，"粗校"仅含简体经文 OCR，**无朱熹注文**；且采用字节跳动反爬，需特殊方式获取正文。

本文记录用识典古籍对校《孟子集注》卷一卷二的经验，方法可复用于其他卷次与四书各经。

## 一、整体流程

1. 获取章节目录（chapterId）
2. Playwright stealth 截获正文 API
3. 提取粗校经文（简体）
4. 与 `text.yaml` 经文逐字比对
5. PUA 损字回填
6. OCR 局限判断（不盲信粗校）

## 二、章节目录获取

识典古籍是 React SPA，SSR（服务端渲染）含**整书章节目录**（`chapterGroups`），但**不含正文**。

访问 book 页（如 `https://www.shidianguji.com/book/HY0004`），`curl` 获取 HTML（UTF-8），用正则提取 `chapterId` + `chapterName` 配对：

```python
import re
s = open('page.html', encoding='utf-8').read()
pairs = re.findall(r'"chapterId":"([^"]*)"[^}]{0,260}?"chapterName":\[\{"content":"([^"]*)"', s)
```

> ⚠️ 不要用 `grep -oE` 在 minified 单行上做跨越式匹配（回溯爆炸会超时）；用 Python `re.findall` 更稳。

《四书章句集注》（书 ID `HY0004`）孟子部分 chapterId：

| 章节 | chapterId |
|---|---|
| 孟子序 | `1juqsp5318mc3` |
| 梁惠王章句上 | `1juqsp7g2t83j` |
| 梁惠王章句下 | `1juqsp7g2tkqn` |
| 公孫丑章句上 | `1juqspa18i70r` |
| 公孫丑章句下 | `1juqspa18ijnv` |
| 滕文公章句上 | `1juqspcs80e95` |
| … | … |

访问单章：`https://www.shidianguji.com/book/HY0004/chapter/<chapterId>?version=32`

## 三、正文 API 截获（关键）

SSR 不含正文，正文由前端 API 异步加载。识典用字节跳动反爬（`a_bogus` / `msToken` / `verifyFp` 签名），**WebFetch 与 curl 直接调 API 均被拒**。

### 反爬表现
- WebFetch：被网络策略阻断（"Unable to verify if domain is safe to fetch"）
- `curl GET /api/ancientlib/read`：`errorCode 40001`（缺参数）
- `curl POST` 带参数：`errorCode 31000`（签名/检测失败）

### 解决：Playwright + stealth

让浏览器 JS 自动生成签名并请求 API，截获响应：

```javascript
const { chromium } = require('playwright');
const b = await chromium.launch({
  channel: 'chrome',                          // 用系统 Chrome（Playwright 自带 chromium 版本可能不匹配）
  headless: true,
  args: ['--no-sandbox', '--disable-blink-features=AutomationControlled']
});
const ctx = await b.newContext({
  userAgent: 'Mozilla/5.0 (X11; Linux x86_64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/146.0.0.0 Safari/537.36'
});
const p = await ctx.newPage();
await p.addInitScript(() => {
  Object.defineProperty(navigator, 'webdriver', { get: () => false });  // 反 headless 检测
});
p.on('response', async (res) => {
  if (res.url().includes('/book/pages/')) {
    console.log('REQ:', res.request().postData());   // 看 API 请求体
    console.log('RES:', (await res.text()).slice(0, 500));
  }
});
await p.goto('https://www.shidianguji.com/book/HY0004/chapter/<chapterId>?version=32',
  { waitUntil: 'networkidle', timeout: 60000 });
```

不加 stealth 时所有 `/api/ancientlib/read/*` 返回 `errorCode 31000`；加上 `channel:'chrome'` + `navigator.webdriver=false` 后返回 `errorCode:0`。

### 正文 API
- endpoint：`POST /api/ancientlib/read/book/pages/v3/`
- body：`{bookId, pageIndex, pageSize, startPageNum, endPageNum, version, needCheckVersion, ptoken, isWebpSupported}`
- 响应：`{errorCode:0, data:{pages:[{pageId, picUrl}]}}` —— **picUrl 是影印图**（`isShowPageImage:true`）

**正文不在 API 响应里**（是图片），而在 **DOM innerText**（前端渲染的粗校文本层）。取 `document.body.innerText` 即得经文。

## 四、经文提取与对校

DOM innerText 含导航 + 经文 + 页脚。提取章名后到 `Next` 前的经文（含 `○` 分章，简体）：

```javascript
const txt = await p.evaluate(() => document.body.innerText);
const start = txt.indexOf('梁惠王章句上');
const jingwen = txt.slice(start, txt.indexOf('Next', start))
  .replace(/\s+/g, '').replace(/○/g, '');
```

识典粗校简体，用 opencc `s2tw` 转繁，与本仓库 `text.yaml` 的 `j` 块经文（繁体）比对。

### 字符多重集比对（找本多/本少，不定位）
```javascript
function diff(a, b) {
  const ma = {}, mb = {};
  for (const c of a) ma[c] = (ma[c]||0)+1;
  for (const c of b) mb[c] = (mb[c]||0)+1;
  const all = new Set([...Object.keys(ma), ...Object.keys(mb)]);
  const more = [], less = [];
  for (const c of all) {
    const d = (ma[c]||0) - (mb[c]||0);
    if (d > 0) more.push(c + '×' + d);
    if (d < 0) less.push(c + '×' + (-d));
  }
  return { more, less };
}
```

### 逐字对齐（定位实质差异）
统一引号（识典用 `" " ' '`，本仓库用 `「」『』`）后逐字贪心对齐，找差异段。引号数量差异多为版本/OCR，**重点看非引号字符的缺字/异字**。

## 五、PUA 损字回填（关键陷阱）

CHM 底本（`input_data/四书章句集注.CHM`）用 **PUA 私有码点**（`&#62451;` 等，`≥ 0xE000`）表示罕见字（私有造字区）。抽取脚本 `tools/extract-*.js` 的 `clean()` 函数会**静默删除 PUA 实体**，导致经文/注缺字（如 `吾&#62451;` → `吾`，缺"惛"）。

**这是 CHM 底本通病，务必扫描**。识典对校能发现（识典有正字）。

### 扫描 PUA
```javascript
const h = new TextDecoder('gbk').decode(fs.readFileSync('NN.htm'));
const re = /&#(\d+);/g; let m;
while ((m = re.exec(h))) {
  if (+m[1] >= 0xe000) {
    const ctx = h.slice(Math.max(0, m.index-90), m.index+90)
      .replace(/<[^>]+>/g, '').replace(/\s/g, '');
    console.log(m[0] + '(U+' + (+m[1]).toString(16).toUpperCase() + '): …' + ctx + '…');
  }
}
```

> ⚠️ **`grep -oE '&#[0-9]+;'` 在 GBK 字节流上可能漏匹配**（实测 28.htm 含 `&#62451;` 但 grep 返回空）。务必用 node `TextDecoder('gbk')` 解码后再扫描。

### 回填正字
PUA 码点无标准映射，正字需上下文推断，三个来源：
1. **CHM 自注**：CHM 注常解释 PUA 字（如 `&#62451;，与昏同` → 惛）
2. **识典经文**：识典有正字（如 `吾惛`）
3. **朱熹注体例**：如 `推己之心以&#60073;民` → 及（"以及民"是朱熹注固定表述）

## 六、OCR 局限判断（不盲信粗校）

识典粗校是简体 OCR，质量不如 CHM 电子本，常见问题：
- **注引文混入经文**：如卷二第一章，识典经文出现 `管籥之音，舉欣欣然` —— 实为朱熹注引文，CHM 经文为 `舉疾首蹙頞`（正确）
- **重复段**：OCR 重复某段
- **错字**

**判断原则**：CHM 是电子本（结构化），识典是 OCR（粗）。差异时查 CHM 原文确认，CHM 正确的不采信识典。识典对校的价值在**发现 CHM 的明确错误**（PUA 缺字、经文误排入注），而非逐字照搬。

## 七、案例：《孟子集注》卷一卷二

### 精校修正

| 问题 | 性质 | 修正依据 |
|---|---|---|
| PUA `&#62451;`(U+F3F3)=**惛**（卷一经文+注） | CHM PUA 造字，`clean()` 误删 → 缺字 | CHM 自注"与昏同" + 识典经文"吾惛"双重印证 |
| PUA `&#60073;`(U+EAA9)=**及**（卷二注） | 同上 | 朱熹注体例"推己之心以及民" |
| 卷一第四章缺"以刃與政"第二问 | CHM 把孟子第二次问**误排入注**（朱熹注"孟子又問而王答也"） | 识典对校发现，依朱熹本补回经文 |
| 卷二第五章注误删 857 字 | 生成脚本 `re.sub(r'〔一〕.*$')` 从**首个**〔一〕删到末尾——而〔一〕在"哿，工〔一〕可反"靠前处 | 改用 `clean_z` 只删末尾校记注脚 |

## 九、注意事项

1. **识典 version=32 影印本**：粗校仅经文，**无朱熹注文**；注文对校需其他源，或依 CHM 底本 + 朱熹体例。
2. **反爬严**：WebFetch 不行，需 Playwright stealth（`channel:'chrome'` + `navigator.webdriver=false`）；纯 `chromium.launch()` 会因版本不匹配失败，且无 stealth 时 API 返回 31000。
3. **PUA 损字**：CHM 通病，务必用 node 扫描（`grep` 不可靠）；扫描后按 CHM 自注/识典/体例三源回填。
4. **OCR 不可全信**：CHM 核对确认后才改，避免照搬 OCR 错（注混入经文、重复段）。
5. **简繁转换**：识典简体，本仓库繁体；opencc `s2tw` 双向转换都有损（引入误转如 征→徵、辟→闢），但底本差异（缺字/异字）仍可发现——opencc 误转两边一致，不构成比对差异。
6. **生成脚本校记处理**：删校记注脚时勿用 `re.sub(r'〔N〕.*$')`（首个〔N〕可能在中间），应只删末尾"〔N〕「字」原作…"段。
