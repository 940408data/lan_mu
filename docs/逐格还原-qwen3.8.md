# 逐格还原验证：qwen3.8-max gridTranscribe 实测

> 本文记录 `gridTranscribe` 逐格转写函数（`src/vision.js`）的首次实测：用覆校模型 qwen3.8-max 对大学章句第 2–9 页做逐格转写，生成 `{col, row, char, start}` 逐格数据，验证能否严格还原 16×15 版面，并统计 token 消耗与费用。

## 1. 背景

`vision.js` 中定义了两类版面网格函数：

| 函数 | 粒度 | 输出 | 用途 | 是否在用 |
|---|---|---|---|---|
| `gridColumns` | 列级 | 每列 `{col, start, text}` | 判经注（M3） | ✅ 在用 |
| `gridTranscribe` | 逐格 | 每格 `{col, row, char, start}` | 严格版面还原 | ❌ 未接入 |

列级数据可做结构正确的版面框图，但存在三个信息缺失：

1. **行号丢失**：列级 `text` 是连续字符串，无法确定每个字在第几行
2. **双行夹注无法区分**：注列两行小字混为一个字符串，无法区分左右行
3. **空行/空格不显式**：无字的格与识别失败的格无法区分

本次实测验证 `gridTranscribe` 能否补齐这三项缺失。

## 2. 实验设置

| 配置项 | 值 |
|---|---|
| 模型 | qwen3.8-max（覆校，`--force-deep`） |
| 网格 | 16 列 × 15 行 = 240 格/页 |
| 测试页 | 大学章句第 2–9 页（8 页，第 10 页网络失败） |
| 并发 | 1（串行，便于准确记录 token） |
| 渲染 | pdftoppm 150 DPI → PNG → base64 |
| 定价 | 输入 ¥12/百万 token，输出 ¥36/百万 token |
| 数据 | `data/大学章句/grid-transcribe.json` + `grid-transcribe-log.json` |

## 6. 对比：列级 vs 逐格

| 维度 | 列级 `gridColumns` | 逐格 `gridTranscribe` |
|---|---|---|
| 输出粒度 | 每列一个对象 | 每格一个对象 |
| 文字定位 | 列级连续字符串 | `{col, row}` 精确坐标 |
| 空格标记 | 无（空列 `text:""` 但无行号） | 显式 `char:""` |
| 双行夹注 | ✗ 两行混为一个字符串 | ✓ 通过 row 区分左右行 |
| 列内空行 | ✗ 无法标记 | ✓ 空格显式标记 |
| 经注判定 | ✓ 只需 start 即可 | ✓ 同样支持 |
| 输出 token | ~3,600（仅文字） | ~11,785（含坐标 JSON） |
| 每页费用 | 更低（未实测） | ¥0.4568 |
| 适用场景 | M3 判经注（当前流水线） | 严格版面还原、复原排版 |

## 7. 结论

1. **逐格还原可行**：`gridTranscribe` + qwen3.8-max 能输出完整的 16×15 逐格数据，每个字有精确的 `(col, row)` 坐标，可严格还原版面。

2. **费用可控**：平均每页 ¥0.46，两书全量逐格转写约 ¥53。主要成本在推理 token（占输出 60–80%）。

3. **列级已够用 vs 逐格更精确**：当前流水线 M3 判经注只需列级 start 信息，`gridColumns` 足够。若需严格版面还原（如复原排版、双行夹注区分），需接入 `gridTranscribe`。

4. **待优化**：
   - 推理 token 占比过高，可考虑关闭思考模式（`enable_thinking: false`）降低推理 token
   - 可尝试初校模型（qwen3.7-plus，¥2/¥8）做初筛，仅复杂页升级覆校
   - 第 10 页网络失败需增加重试机制
